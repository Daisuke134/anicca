# Delegation Brief Template (Five Parts)

Write every delegation — to a subagent, a teammate agent, or a scheduled
loop — as a five-part brief that hands over an *ongoing result*, not the
next action.

Sources: David Ch, "How to master Muse" (X, 2026-09-26: "Give it an
ongoing result, not merely the next action"); aiagentslibrary.com, "100 Best
Meta Muse Prompts For Work" (five-part formula, test-lab scored);
museexplained.com, "How to Use Muse: The Complete Guide" (delegate, don't
chat; the one-job rule).

## The template

```markdown
[Subagent Task]: <one-line title>

(1) Ongoing outcome
The state that must keep being true when this work is done — not the next
step. One sentence, naming the artifact and the count.
Why, in one line: which product grows, who uses it, how it becomes revenue.

(2) Context you may use
The exact accounts, files, ledgers, and links the worker may use. A file
that merely exists in a workspace is not context — name it, and paste
critical facts inline, because a child agent does not inherit later
corrections. Anything unverifiable is labeled "unconfirmed".

(3) Boundaries
What must not happen: surfaces not to touch; the single-writer rule for any
shared surface; no credential values in files or chat; no step that routes
a question, approval, code, or tap to a human; any banned routes for this
task, named explicitly so the worker switches routes instead of waiting.

(4) Stop conditions and internal handling
When a step is blocked: record the blocker and its concrete unblocking step
in the working notes, treat it as an internal jam, and keep every other part
of the work moving. If one item's publishability is doubtful, exclude only
that item and publish the rest, logging the exclusion reason.

(5) Definition of done
A verified artifact, not a status: the final output opened and read in
full, arrival confirmed on the counterpart side (the public URL loads, the
ledger row exists, the recipient-side state changed). Every deliverable
carries a "could not confirm" list; unknowns are marked unconfirmed and
never smoothed over with plausible values.
```

## Rules that make the template work

- **Calibrate before you scale.** The first delegation of a new kind is one
  job whose wrong answer you would recognize immediately (the one-job rule).
- **Two consecutive hand successes before anything becomes a loop**, and
  verify a new loop's first two runs against the artifact itself before
  calling it "running". A loop with a bad brief does not fail once; it fails
  on a schedule.
- **Close the loop on every run.** Compare the result against the brief, not
  against effort. Write each correction as one permanent sentence into the
  brief, the loop body, or the owning skill, the same day it is learned, so
  the same mistake is not re-taught next week.
- **Receipt before credit.** A delegation counts as delivered only when the
  worker confirms receipt; a message sent to an offline worker is
  undelivered, not coordinated.
