## 0. 結論（1行）

> **課金は「会話が今どれだけ太っているか」×「あと何ターン続けるか」で決まる。**
> **セッションを長く続けること自体が、二次関数的に金を焼く。** 床でも TTL でも cron でもない。

## 1. 決定的な実データ — 1ターンの cache_read が単調に太る

セッション `79938ece`（2026-07-13 01:16〜03:54、対話メイン、Opus）:

| **合計** | **平均 279,642 tok/turn** | **154.9M tok = $77.46**（Opus cache read $0.50/M） |

**1つのセッションだけで $77。** 最後の方は**1ターン打つたびに 434,000 トークンを読み直している**。

床（51k）は、この 280k のうち **18% にすぎない**。残り 82% は**会話そのもの**（貼った出力・ツール結果・私の長文）。
床を掃除しても溶け続けたのは当然だった — **掃除した場所は問題の 18% でしかなかった。**

### 物理（なぜ二次関数か）

```
1ターンの費用 ∝ その時点の文脈サイズ
文脈サイズ    = 床 + Σ(それまでに積んだ全部)   ← ターンごとに増える、減らない
セッションの総費用 = Σ_{t=1..N} 文脈(t) ≒ 床×N + 傾き×N²/2
                                              ^^^^^^^^^^^  ← ターン数の二乗
```
**ターン数を2倍にすると、費用は約4倍になる。** 「まだ喋ってるだけ」で指数的に燃える理由がこれ。

## 3. 棄却された仮説（＝掃除しても効かなかった理由）

| 仮説 | 実測 | 判定 |
|---|---|---|
| **5分 TTL 失効で払い直している**（私の最有力仮説） | 5分超のギャップに起因する再書き込みは **全 cache_creation の 7.8%**。しかも今日の cache_creation の **95% は `ephemeral_1h_input_tokens`（1時間TTL）** | **棄却** |
| OpenClaw の cron 222件が Claude を焼いている | jobs.json に `claude` 直呼びは **0件**。全部 codex/deepseek 経由。ccusage 上も **$0.55** | **棄却** |
| 起動時の床（skill/CLAUDE.md/MCP） | 51k = 実際の 1ターン 280k の **18%** | **主犯ではない**（効いたが小さい） |
| 並行セッションが原因 | 公式に gotcha はある（下記）が、金額の主因は各セッションの**長さ**の方 | **副次的** |

公式（`docs.claude.com/prompt-caching`）:
> "The cache is refreshed for **no additional cost** each time the cached content is used."
> "For concurrent requests, note that a cache entry only becomes available after the first response begins."

→ 会話が続く限り TTL は無料で延びる。**同時に3本起動すると後発2本は cache hit を取り損ねる**（＝起動は数十秒ずらす）。
→ **1時間TTL を Claude Code から明示制御することはできない**（API 直叩き専用）。この線は追わない。

## 4. 真因ランキング（実数字つき）

| 順 | 真因 | 根拠 |
|---|---|---|
| **1** | **長時間・多ターンの対話セッション**（文脈が太ったまま続く） | 上位2セッションだけで今日の自前集計 224M のうち **76%**。1セッション $77。1ターン 434k まで肥大 |
| **2** | **文脈を太らせる行為 = 生ツール出力の貼り付け**（傾きを上げる） | 床 51k に対し実測 280k。差の 229k は会話が積んだもの |
| 3 | 常駐 tmux の self-fix ループ（`anicca-selffix-gig-loop`、context 166.3k を抱えたまま idle 常駐） | 「既知の外部ブロッカーを 400〜1400分かけて再調査した」と**プロンプト自身が自認** |
| 4 | 毎時 :45 の gig reality-verifier（fresh spawn ×4本 = 約 3M tok） | 実測 |
| 5 | 3本同時起動による cache miss | 公式 gotcha（金額寄与は未実測） |

★ **Opus の 1M コンテキスト窓が、この病気の enabler になっている。** 200k 窓なら auto-compact が強制的に文脈を畳むが、
1M 窓では **434k まで太っても何も止めない**。窓が広い = 安全ではなく、**ブレーキが外れている**という意味。
