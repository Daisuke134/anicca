## 一行で

**エッジは「無い」のではなく、「今この瞬間は測定できない」。** カバー範囲の改善は成功したが（突合可能な市場は 100 → 499 に増えた）、Pinnacle が持つ「明日の試合」と Polymarket が listing 済みの「今日の（すでに始まっている）試合」が時間的に重ならず、**比較可能な試合が 0 件**になった。エンジンは比較不能なものを無理に比較することを拒否している。これは失敗ではなく、設計通りの fail-closed である。

## ★ 実測して初めて分かった、3つの「偽エッジ」 ★

**この作業で最も価値があったのは、エッジを見つけたことではなく、偽エッジを4つ潰したことである。** どれも実弾で賭けていれば損失だった。すべて「実際に走らせて数字を疑った」から見つかった。

### 偽エッジ 1: 決着済みの試合（+97,147%）

初回ライブ実行のトップが `McKinney` — Polymarket $0.0005 に対し Pinnacle fair 48.6%。**試合はすでに終わっていた。** 市場は彼が負けるのを見て価格を0に落とし、Pinnacle のラインだけが試合前の数字のまま残っていた。買えば毎回100%失う。
→ `is_prematch()` で除外。

### 偽エッジ 2: 連戦の別試合と比較していた（+39.6pt / +20.8pt）

MLB は同じカードを複数回やる。Pinnacle には Cubs@Reds が2試合あった：
- `2026-07-11T23:11Z`（すでに進行中）
- `2026-07-12T17:41Z`（明日、試合前 → `is_prematch` を通過）

一方 Polymarket の「Chicago Cubs vs. Cincinnati Reds」市場の `gameStartTime` は `2026-07-11 23:10` — **今日の、今まさに進行中の試合**だった。

つまり「**明日の試合の Pinnacle オッズ**」と「**今日の進行中の試合の Polymarket 価格（Cubs が勝っている）**」を比較していた。Reds を 6.5% で買う——だが Reds は今まさに負けている。
`is_prematch()` は Pinnacle 側の時刻しか見ておらず、**Polymarket 側が同じ試合かを一度も確認していなかった**。
→ `match_market()` に `gameStartTime` の一致検証（許容差3時間、fail-closed）を追加。

**+20.8pt は `max_edge`（30pt）を通過するため、実際に賭けられていた。**

### 偽エッジ 3: 3択のオッズを2択の市場と比較していた（-18.5pt）

```
Pinnacle の soccer h2h は3択:
   France +136 / Spain +229 / Draw +227    → France が「90分で勝つ」確率 41.0%

マッチした Polymarket 市場:
   "France vs. Spain: Team to Advance"      → France が「勝ち上がる」確率 59.5%（延長・PK込み、2択）
```
**別の質問である。** 90分で勝つ確率と、PK込みで勝ち上がる確率は違って当然で、両方正しい。エッジではない。
→ `find_edges()` で Pinnacle h2h の選択肢が2でない試合を除外（Draw の確率を勝手に再配分することは数学的に不可能なので fail-closed）。

### 偽エッジ 4（私の報告そのもの）: ニュース記事の古いオッズ（+29.4%）

セッション途中、firecrawl で拾ったニュース記事の DraftKings オッズ（McGregor +185）から「+29.4% のエッジ発見」と報告した。**本物の Pinnacle ライブラインで検証すると McGregor は Pinnacle 27.1% / Polymarket 27.5% = 差 0.4pt。エッジは存在しなかった。**
検索して得た情報を、検証せずに使った。同じ過ちである。

**4回中4回、「エッジを見つけた」は間違いだった。**

## なぜ今 0 件なのか（timing の問題であって、edge の不在ではない）

```
現在 02:00 UTC

Pinnacle が持つ MLB     : 明日の試合（2026-07-12 17:41 等）→ 試合前 ✓
Polymarket が listing 済 : 今日の試合（2026-07-11 23:10 開始、進行中）

→ 同じ試合が「両方に、試合前の状態で」存在する瞬間が、今はない
```

Polymarket は試合が近づいてから市場を立てる。したがって**重なる時間帯にスキャンすれば比較できる**。ループは 20-90 分ごとに起きるので、その窓に自然に当たる。1日5スキャンの credit 予算はコードで強制済み。

## 結論と、次にやること

1. **エンジンは正しい。** 3つの偽エッジを自動で拒否し、比較不能なときは黙って「機会なし」を返す。32/32 テストがそれを固定している。
2. **エッジの有無はまだ判定できていない。** 比較可能な試合が 0 件では、「乖離が何pt あるか」の分布そのものが取れない。**「エッジは存在しない」とは言えないし、「存在する」とも言えない。**
3. **次**: ループに組み込んで回し、**比較可能な試合が実際に現れる時間帯のデータを集める**。数十試合の乖離分布が取れて初めて、「このエッジは実在するか」に答えが出る。
4. **それまで実弾は賭けない。** n=0 で賭けるのは、このドキュメントが記録した4つの過ちの5つ目になる。

**負の結果・測定不能という結果を、正直に書き残すこと自体が成果である。** 「+29.4% のエッジ発見」と言い続けるより価値がある。
