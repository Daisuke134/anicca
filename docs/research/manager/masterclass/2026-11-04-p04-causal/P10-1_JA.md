## 1. この講義の問い：AIが正しく予測できたとして、価値はあるのか

Phase 9は「未知の人物・研究・文化で予測できるか」を問う。Phase 10は別の問いに進む。「利用者に価値ある仕事が、どのくらいの成功確率と費用で完了し、実際の収益・損失・人の負担としてどう確認されたか」。**予測正解、仕事の完了、入金、会計上の売上、利用者の便益は違う。**

単位（unit）はAPI呼出やトークンでなく、顧客の目標に対応する**1件のwork_item_id**。1件の中に複数の推論、ツール、再実行、停止、失敗があり得る。成功は第三者ソースによる確認を必要とする。

## 2. 最低限の数学

仕事 j の認識済み純売上を R_j、変動原価を C_j と置く。

- R_j = 会計規則に基づく認識売上 − 同期間に対応する返金・値引・チャージバックの調整。請求書、決済、口座着金、収益認識は別イベントとして保持する。
- C_j = 推論API + 自社ホスティングの配賦変動費 + エージェントツール + 外部API + 決済手数料 + 顧客対応 + 人の介助 + 返金対応の変動費など（重複除外）。固定的なクラウド契約は配賦方法と原価区分を指定する。
- **仕事別貢献利益 CM_j = R_j − C_j**。
- **貢献利益率 = ΣCM_j / ΣR_j**。ΣR_j が0なら未定義（0%とはしない）。
- **成功1件当たり費用 = Σ（失敗・再試行・NO_ACTIONも含む対象仕事の費用） / 外部確認済み成功件数**。分母0なら未定義。
- **営業利益は別**。期間の貢献利益から共通固定費、人件費、販売管理費など適切な費用を控除。CMを最終純利益と呼ばない。
- **増分貢献利益**はManager群と対照群で、割付された全対象単位の平均利益を比較して初めて検証する。良い事例だけを抜き出す選択バイアスは禁止。

モデルの実効推論費用は、課金入力/出力/キャッシュ/推論トークンのカテゴリと適用単価・割引・年月・通貨を持って計算する。初期推計は estimate、請求・利用レポートを使ったreconciledとは区別する。無料枠利用は請求額0でも、資源使用ゼロや永続的コスト0を意味しない。

## 3. 完全架空の3件で計算

単位USD。下記の金額・仕事は**すべて架空**。人の介助費は作業時間×配賦時給の例であり、実際の従業員や費用ではない。

| 仕事 | 独立確認した結果 | 認識純売上 | 推論 | ツール | 人の介助 | 決済等 | 変動費合計 | 貢献利益 |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| A | VERIFIED_SUCCESS | $5.00 | $0.30 | $0.40 | $0.00 | $0.20 | $0.90 | +$4.10 |
| B | VERIFIED_FAILURE | $0.00 | $0.80 | $0.50 | $1.00 | $0.00 | $2.30 | −$2.30 |
| C | NO_ACTION | $0.00 | $0.10 | $0.00 | $0.00 | $0.00 | $0.10 | −$0.10 |
| **合計** | **成功1/3** | **$5.00** | **$1.20** | **$0.90** | **$1.00** | **$0.20** | **$3.30** | **+$1.70** |

よって成功1件当たり費用は **$3.30 / 1 = $3.30**、試行された仕事1件当たりの変動費は$1.10。成功仕事Aだけ見た$0.90を「成功当たり費用」とするのは、失敗Bと安全停止Cの費用を隠してしまう。売上が確認されても利用者の心理的便益は**NOT_MEASURED**である。

## 4. 人の介助を隠さない：Autonomyの測定

- **human_touch_count**：顧客・第三者を含め、仕事の完了に必要だった人手の介入回数。ゼロは観測して確認できたゼロに限る。
- **human_assist_seconds**：本人確認、内容修正、再実行、エスカレーション、エラー復旧などの実測秒数。
- **assist_cost**：seconds / 3600 × fully-loaded hourly rate。レートの根拠・通貨・雇用区分・適用期間も残す。
- **unassisted_verified_success_rate**：人の実作業なしで外部確認された成功 / eligibility条件を満たす全仕事。単なる「エージェントが完了と自己申告した割合」ではない。
- **human_rescue_rate**：人が救済しなければ未完了だった仕事 / 全対象仕事。介助と強制的な法令遵守・安全承認の違いも分ける。
- **UNKNOWN** と **NOT_INSTRUMENTED** は0に変換しない。人の介入が記録されない環境で「ゼロヒューマン達成」と宣言しない。

自律性を高めることは目標にできるが、人の安全や必須の承認・本人の撤回権まで削減する対象にしない。

## 5. 「台帳」は新しい会計正本ではなく、既存証拠の検証可能な投影

~~~text
work_item_id（利用者の一つの目標）
  ├─ attempt_id / trace_id（再試行を含む実行の軌跡）
  │   ├─ 推論usage + 固定した単価版 → model_cost
  │   ├─ ツールreceipt + provider請求 → tool_cost
  │   ├─ 人の介入イベント + 秒数 + レート → assist_cost
  │   └─ 外部readback + 安全判定 → outcome
  ├─ 請求 / 決済 / 認識売上 / 返金 → revenue
  └─ provenance + as-of cutoff → read-only unit economics
~~~

既存runtimeの権限、outbox、独立readbackを再利用する。請求・会計正本を別の学習ファイルに複製しない。生個人情報、プロンプト本文、医療情報は原則として分析投影へコピーしない。

## 6. 資料をつなぐキーとデータ品質

一つのジョブのキーは tenant_id / work_item_id / attempt_id / trace_id。お金のイベントは source_ref / provider_event_id / event_id / occurred_at / recorded_at / currency / amount_minor を含む。費用の帰属不能は**UNALLOCATED**で残し、「適当に按分して消す」ことをしない。イベントは追記型、重複provider_event_idは除外、修正はreversal＋再計上で追跡する。複数通貨は当日為替レートを明記し、換算前の原額・通貨を保持する。

収益認識は現金入金と混同しない。ツール側の「送信成功」と利用者の「結果が発生した」も混同しない。遅延確定があれば2026-11-07時点のas-ofを記録し、後日結果を事前予測に混入しない。

## 7. 毎日の最小KPI

1. **Confirmed contribution margin per eligible work item** = 期間内割付全対象仕事の確認済み貢献利益 / 対象仕事数。未確定費用・売上割合とセットで報告。
2. **Cost per independently verified success** = 失敗を含む全対象変動費 / 独立成功件数。
3. **Human rescue rate** = 救済介入した仕事 / 対象仕事数。

ガードレール：権限外実行、撤回無視、苦情・損害、独立検証の欠測率、費用帰属不能率。心理的便益は本人が選んだ尺度と比較群を使い別パイプラインで検証。利益が正でも害があればNO_ACTION/DO_NOT_SHIP。

## 8. P10-1の受入基準と未完了

受入（教育・ソフトウェア）：
1. 同じ3件の架空データから売上・全費用・利益・介助を再計算できる。
2. 失敗・再試行・NO_ACTIONにかかった費用を成功当たり費用から除外しない。
3. 重複event_id、未証拠収益、通貨混在、未取得を拒否・区別できる。
4. source_ref、as-of、責任範囲を追跡できる。
5. 人間の便益は収益と別軸、未測定は未測定のまま表現する。

未完了：本番会計のreconciliation、実仕事と決済の端から端までの結合、第三者確認の実成功率、コホート別の増分貢献利益・人の心理的便益。**これらは本講義だけでは実証されない。** BFM-01/02とINT-02の未完了も維持する。
