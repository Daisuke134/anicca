## 1. 実験の問い・単位・アウトカム

例として、自社の公開支援ページで「正しい公的機関のリンクを一定時間内に見つけられるか」を比較すると考える。

- **A群：** 現行の案内ページ（比較）。
- **B群：** 操作しやすい案内ページ（候補。未公開）。
- **主要評価：** `Y_i = 1` if 正しい公的情報を定めた時間内に見つける、そうでなければ0。
- **割当単位：** 原則として本人単位。複数回訪問を独立な個人として数えない。
- **推定する量：** `p_B - p_A`、すなわち絶対的な成功率差。
- **Guardrail：** 正解ではないサイトへ誘導、苦情、離脱、個人情報、リンク破損、公開サイト停止。
- **承認：** 本人に必要な説明と同意・撤回、サービスの実行権限、必要な研究審査。

これは研究の**設計案**であり、実際に募集済み・ランダム化済みではない。現行の公的案内サイトManifestにも`real_participants=0`、`beneficiary_outcome=NOT_MEASURED`と表示されている。

## 2. statsmodelsを使って必要標本数を計算

仮定：現行成功率25%、改善後28%、最小検出効果は**+3パーセントポイント**、両側alpha=0.05、検出力80%、1:1割当。

```python
from statsmodels.stats.power import NormalIndPower
from statsmodels.stats.proportion import proportion_effectsize

p_control = 0.25
p_treatment = 0.28
effect_size = proportion_effectsize(p_treatment, p_control)
n_per_arm = NormalIndPower().solve_power(
    effect_size=abs(effect_size), alpha=0.05,
    power=0.80, ratio=1.0, alternative="two-sided",
)
```

- `NormalIndPower()`は、2群のZ検定について標本数・検出力を求める公式クラス。
- `proportion_effectsize()`は2つの比率をCohenの`h`という標準化効果量に変換。
- `solve_power()`はalpha、検出力、効果量、群の大きさの比などから未知の項目を求める。
- `ratio=1.0`はA/Bが同数、`alternative="two-sided"`は改善・悪化の両方向を調べる。
- 結果を`ceil`で切り上げ、各群の必要人数にする。

**実計算結果：**
| 設計 | 各群の解析必要人数 | 15%脱落を見込んだ募集総数 |
|---|---:|---:|
| 事前に決めた最後の時点で1回検定 | **3,395** | **7,990** |
| 4回の有効性判断を`alpha/4=0.0125`で保守的に補正 | **4,824** | **11,352** |

この計算は**基準25%、MDE+3pt、独立な個人単位**という仮定に依存する。現実のアクセス数、基準正解率、離脱、干渉、学校/世帯クラスターなどを確認せずに確定人数としない。現時点で実参加者は0なので、そもそも本実験は開始できない。

出典：Statsmodels公式 https://www.statsmodels.org/stable/generated/statsmodels.stats.power.NormalIndPower.solve_power.html

## 3. 途中で何度も見ると「偽の成功」が増える

現実に介入の効果が**本当に0**であるA/Aを2400回生成。各繰返しでデータが100、200、300、400人/群まで集まった時点のt検定を見る。

```python
for index, n_per_arm in enumerate((100,200,300,400)):
    result = ttest_ind(
        treatment[:, :n_per_arm], control[:, :n_per_arm],
        axis=1, equal_var=False
    )
    pvalues[:, index] = result.pvalue
```

- `ttest_ind`はSciPyの**既存の**独立2標本t検定。
- `axis=1`で各繰返しの人物方向を比較し、2400回を効率よく計算。
- それぞれの時点で結果を見た場合のp値を保存。
- `np.any(p<0.05, axis=1)`は、4時点の**どこか1回**が偶然有意になったら成功としてしまう誤りを再現する。
- `p<0.05/4`はBonferroniによる保守的な家族内誤検出率の制限。

**実測結果（人工2400回）：**
| 評価方法 | 効果ゼロなのに有意とした割合 |
|---|---:|
| 固定した最後の1回だけ | **4.79%** |
| 4回のどこかでp<0.05になれば停止 | **11.92%** |
| 4回すべてp<0.0125で判定 | **3.79%** |

これは有限モンテカルロの推定であって、毎回11.92%になる定数ではない。**Bonferroniは安全側の教育例であり、StatsigのmSPRTを実装したという主張ではない。**

Statsigは逐次検定と補正済み信頼区間を、Spotify Confidenceは常時有効な検定やGuardrailを提供。継続監視が必要な本番実験では、既存製品/検証済みOSSを優先する。

- Statsig公式：https://docs.statsig.com/experiments/advanced-setup/sequential-testing
- Spotify Engineering：https://engineering.atspotify.com/2024/3/risk-aware-product-decisions-in-a-b-tests-with-multiple-metrics

## 4. Sample Ratio Mismatch（SRM）を先に検査

本来の割当が50:50なのに、結果として560:440なら、ランダム化処理の不具合やログの偏りを疑う。

```python
from scipy.stats import chisquare
result = chisquare([560,440], f_exp=[500,500])
```

実計算で`p=0.0001478023`となり、仮定した品質ゲート`p<0.001`に違反。**このとき効果量がどれほど良く見えても導入判断しない。** 例として505:495は問題なし。SRM自体はあくまで品質検査で、真の交絡を完全に排除する証明ではない。

出典：Microsoft ExPのSRM警告 https://www.microsoft.com/en-us/research/articles/alerting-in-microsofts-experimentation-platform-exp/

## 5. 安全停止と有効性の早期判断は違う

- 本人が害を受ける、権限外操作、費用上限、重大なプライバシー違反は、**統計的有意差を待たずに即停止**する条件を決めてよい。
- 「製品が良くなったから早く公開したい」という判断は、事前に固定した逐次検定・group sequentialなどが必要。
- 観測数や欠測、SRM、帰属してはいけない人工出力などの**データ品質**は成功とは別の必須条件。
- 対照に対する改善、許容可能なGuardrail、外部の独立実結果、費用や撤回可能性が揃うまで本番採用を保留する。
