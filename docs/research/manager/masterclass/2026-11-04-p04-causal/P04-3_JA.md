## 1. まず「模擬RCT」を文章で定義する：Target Trial Emulation

観察データ分析を始める前に、本来どんなRCTを実施したかったか書き出す。

| 項目 | 架空通知の例 | なぜ必要か |
|---|---|---|
| 対象 | 前日までに機能を登録したユーザー | 後で恣意的に対象者を変えない |
| Time zero | 2026-11-01 09:00（架空） | 介入、追跡開始、適格性の時間を合わせる |
| 処置 A=1 | 朝9時の固定文面の通知を1回送信 | 「通知」という介入を特定する |
| 比較 A=0 | 同日、追加通知を送らない | 何と比較した効果なのか特定する |
| 結果 Y | 翌日までのタスク完了 0/1 | 全群で同じ定義・窓を使う |
| 交絡 X | 介入前の意欲・前週利用状況など | 予測要因のうち因果調整に必要なものを決める |
| 推定対象 | この対象集団のATE | 対象が変われば効果も変わり得る |
| 害 | 通知拒否、離脱、負担、同意撤回 | 成功率だけでは施策を承認しない |

選抜を処置後の結果で行うとimmortal time bias等が起こり得る。時系列の定義と許可範囲をP00-3で確定するまで、本番の介入には進まない。

## 2. 識別の4条件と反実仮想

二値介入を `A ∈ {0,1}`、介入前に測定した交絡因子を `X`、結果を `Y` とする。

**条件1｜条件付き交換可能性（Conditional exchangeability / No unmeasured confounding）**

\[
(Y(1),Y(0))\perp A\mid X
\]

同じXを持つ人では、介入を受けた人と受けていない人の潜在的な結果の分布が比較可能だという仮定。**観察データだけでは一般に証明できない**。測れていない意欲、季節要因、同意・選抜などが残る可能性がある。

**条件2｜重なり（Positivity / Overlap）**

\[
0<P(A=1\mid X=x)<1
\]

対象集団で現れるXの各値について、通知あり・なしの両方が可能であること。例えば高リスク層に必ず通知する運用なら、その層の「通知なし」の結果はデータから学べない。

**条件3｜整合性（Consistency）**

\[
Y=Y(A)
\]

観測された結果と、実際に受けた特定の介入の潜在結果が対応すること。通知の文面・強さ・時間が違うのに一つの `A=1` にまとめると、曖昧な処置になる。

**条件4｜干渉なし（SUTVAのうちno-interference）**

他者への介入が本人の結果を変えないという単純なモデル化。SNS、口コミ、家族、会社内、マーケットの相互作用では破れる。より一般には割当ベクトル全体で潜在結果を定義する必要がある。

**重要**：AIPWやTransformerを使っても、条件1・2を自動的に満たせるわけではない。

## 3. どこで調整するか：DAGとバックドア

```text
X：介入前の意欲 → A：通知 → Y：完了
       └────────────────→ Y
```

`A ← X → Y` というバックドア経路を、**適切に測定された介入前のX**で遮断することが目的。これと違って次のDAGでは危険がある。

```text
A：通知 → S：回答したか ← U：意欲 → Y：完了
```

アンケート回答者 `S=1` のみを分析すると、collider `S` に条件付けしてAとUの見かけ上の関連を作り得る。また `A→M→Y` の媒介Mを調整すると総効果を部分的に削ってしまう。**「変数を全部入れる」は因果推論ではない。**

## 4. 識別公式：g-formula（標準化）

前述の仮定のもとで、観察から平均潜在結果を識別する公式は

\[
\begin{aligned}
E[Y(a)]&=E_X[E[Y\mid A=a,X]]\\
ATE&=E_X\{E[Y\mid A=1,X]-E[Y\mid A=0,X]\}.
\end{aligned}
\]

離散Xなら

\[
ATE=\sum_x\bigl(E[Y\mid A=1,X=x]-E[Y\mid A=0,X=x]\bigr)P(X=x).
\]

### 架空世界の完全な数値計算

P04-1と同じ設定：意欲の高い人・低い人が50%ずつ。高い人は80%の確率で通知を受け、低い人は20%の確率で通知を受ける。通知の真の効果は両グループで−10ポイント。

| X=介入前意欲 | P(X) | P(A=1\|X) | Y確率：通知あり | Y確率：通知なし | 群内の差 |
|---|---:|---:|---:|---:|---:|
| 高い | 0.5 | 0.8 | 0.70 | 0.80 | −0.10 |
| 低い | 0.5 | 0.2 | 0.10 | 0.20 | −0.10 |

単純な観察差は `0.58 - 0.32 = +0.26`。しかし標準化すると：

\[
ATE=0.5(0.70-0.80)+0.5(0.10-0.20)=\boxed{-0.10}.
\]

意欲が高い人の比率を「通知あり集団」の80%ではなく、**対象人口の50%**で再合成することがポイント。これは施策を全人口に適用した仮想世界の平均を作る計算である。

## 5. 回帰調整（Outcome Regression / G-computation）

結果を予測するモデルを作る。

\[
m_a(x)=E[Y\mid A=a,X=x].
\]

各人について `m_1(X_i)` と `m_0(X_i)` を推定し、平均との差を求める。

\[
\widehat{ATE}_{g}=\frac{1}{n}\sum_{i=1}^{n}\bigl(\hat m_1(X_i)-\hat m_0(X_i)\bigr).
\]

今回のコードでは、二値Xに対して

\[
Y=\beta_0+\beta_1A+\beta_2X+\beta_3AX+\varepsilon
\]

という飽和OLSを最小二乗法で学習。`AX`は処置と意欲の交互作用で、各層の処置効果を異なる値にできる。線形確率モデルは0〜1の外に予測する場合があるため、一般には適切なリンクや機械学習を検討する。**予測モデルの精度が高いことだけでは未測定交絡の不存在は保証しない**。

## 6. 傾向スコアと逆確率重み付け（Propensity Score / IPW）

介入を受ける確率を、介入前の特徴量からモデル化する。

\[
e(x)=P(A=1\mid X=x).
\]

受け取りやすい人を軽く、受け取りにくい人を重くする。母集団での平均を再構成するHorvitz–Thompson型の式は

\[
\widehat{ATE}_{HT}=\frac1n\sum_i\left[\frac{A_iY_i}{\hat e(X_i)}-\frac{(1-A_i)Y_i}{1-\hat e(X_i)}\right].
\]

実装は正規化したHájek型で、二群の重み付き平均を差し引く。有限標本でHTと完全一致する必要はない。

- 高意欲で通知を受ける確率0.8の人：通知ありの重み `1/0.8=1.25`。
- 低意欲で通知を受ける確率0.2の人：通知ありの重み `1/0.2=5`。

**少なかった低意欲の通知ありケースを大きく補正する。** 一方で e(x)が0や1に近いと重みが極端になり、推定の分散や外挿リスクが増える。重みの分布、最大値、有効標本サイズを必ず確認する。

## 7. Matching（マッチング）

処置を受けた人に、介入前のXが似た未処置の人を対応させる。この講義のコードは意欲の高低が完全に一致する比較を行い、**処置群に対する平均効果 ATT** を推定する。

\[
ATT=E[Y(1)-Y(0)\mid A=1]
\]

ATTとATEは対象人口が違う。今回は人工的に効果を両層で同じ−10ポイントに設定したので理論値が同じになるだけ。異質な効果があれば異なる可能性がある。マッチできなかったケースを捨てれば、推定対象も変わることに注意。

## 8. AIPW：結果モデルと介入モデルを組み合わせる（二重ロバスト）

二種類のモデルを同時に使う。

- 結果モデル `m_a(x)`：行動aを選んだ場合の結果を推定。
- 介入モデル `e(x)`：行動aがログ上で選ばれた確率を推定。

\[
\widehat{ATE}_{AIPW}=\frac1n\sum_i\left[\hat m_1(X_i)-\hat m_0(X_i)
+\frac{A_i(Y_i-\hat m_1(X_i))}{\hat e(X_i)}
-\frac{(1-A_i)(Y_i-\hat m_0(X_i))}{1-\hat e(X_i)}\right].
\]

角括弧の最初はモデルの反実仮想予測。後ろの二項は、観測された人の予測誤差を、選択確率で補正する。

この推定量は、適切な正則条件・識別仮定のもと、**結果モデルか処置モデルの少なくとも一方が正しく指定されていれば**一致性を持つという意味で二重ロバスト。ただし「未測定交絡があっても大丈夫」「小標本でも必ず正しい」という意味ではない。

機械学習を使って高次元のXを扱う場合、過学習への対応としてcross-fitting（別のfoldで学習し、未学習foldを評価）や適切な信頼区間が重要になる。今回の教材は飽和した二層モデルの最小例で、**cross-fitting、クラスターロバストSE、実データでの感度分析は未実装**。

## 9. DiD：同時期の比較ではなく、「変化の差」を使う

Difference-in-Differences（差の差法）では、導入前後に測った二群の変化を比較する。

\[
\widehat{DiD}=(\bar Y_{T,post}-\bar Y_{T,pre})-(\bar Y_{C,post}-\bar Y_{C,pre}).
\]

別の架空例：

| グループ | 施策前 | 施策後 | 変化 |
|---|---:|---:|---:|
| 施策導入グループ | 30% | 38% | +8pt |
| 非導入グループ | 20% | 25% | +5pt |
| **DiD** | | | **+3pt** |

これは**P04-1の通知の−10ポイントとは別の独立した架空例**。3ポイントを因果効果とみなすためには、介入がなかった場合に二群の結果の変化が等しかったという**平行トレンド（parallel trends）**をはじめ、先取り行動なし、群構成の変化や干渉、同時期の別施策などについて適切な仮定が必要。

導入時期がグループでずれるStaggered DiDでは、単純なtwo-way fixed effects（TWFE）が異なる処置時点や異質性を不適切に混ぜる場合がある。Callaway & Sant'Anna等の推定対象を検討する。事前のトレンド図は検証の助けになるが、将来の平行トレンドを証明はできない。

## 11. Python重要コード：一行ずつ

```python
u = rng.binomial(1, 0.5, size=n)
propensity = np.where(u == 1, 0.8, 0.2)
a = rng.binomial(1, propensity)
y = np.where(a == 1, y1, y0)
```

1. `rng.binomial(1,0.5,size=n)` はn人について0/1を50%ずつの確率で生成する。`rng`は固定シードの乱数生成器。
2. `np.where(条件,真のとき,偽のとき)` は配列の各人について処置確率を決める。高意欲なら0.8、それ以外は0.2。
3. `rng.binomial` の第2回目は **本人の意欲に依存して処置Aを割り当てる**。RCTではなく交絡した観察ログ。
4. `y1,y0` は実データで同一人について両方観察できない潜在結果。人工世界なので生成器が両方を保存して、選択されたほうだけ `y` に出す。

```python
m = stratum_means(y, a, u)
ate = sum(np.mean(u == x) * (m[(x, 1)] - m[(x, 0)]) for x in (0, 1))
```

- `stratum_means` は `U=0/1 × A=0/1` の4セルについて、それぞれ観測結果 `Y` の平均を計算する。空セルがあれば識別不能として例外を投げる。
- `np.mean(u==x)` は全員のうち介入前意欲 `x` を持つ人の比率。
- `m[(x,1)]-m[(x,0)]` はその意欲層内の通知あり/なしの平均結果差。
- `sum(...)` は層内の差を**元の母集団構成**で加重平均し、ATEを得る。

```python
e = estimate_propensity(a, u)
w1 = (a == 1) / e
w0 = (a == 0) / (1 - e)
ipw = np.sum(w1 * y) / w1.sum() - np.sum(w0 * y) / w0.sum()
```

- `estimate_propensity` は意欲層ごとに `P(A=1|U)` を観測頻度から推定する。Yを使って処置確率を学習しない。
- `w1` は通知群だけが正の値となる逆確率重み。低い受信確率の人ほど重い。
- `w0` は比較群の同様の重みで、分母は `1-e`。
- `np.sum(w1*y)/w1.sum()` は正規化重み付き平均。二群の差がHájek IPW推定量。
- **必須**：eが0または1なら割算が成立しないので、実装では`validate_overlap`を先に呼ぶ。

AIPWの式は `aipw()` にそのまま実装している。`did()` は別の前後比較を扱い、このデータのATEに加算しない。

## 12. Managerへの接続：介入候補の評価パイプライン

```text
[許可された過去ログ]
       ↓
対象・time zero・処置・結果・estimandの事前定義
       ↓
DAG / 交絡因子 / 干渉 / データ権利の検査
       ↓
Overlapチェック → 不十分なら「識別不能」で停止
       ↓
Outcomeモデル m_a(x) ＋ 行動方策 e(x)
       ↓
g-formula / IPW / AIPW の感度比較
       ↓
未測定交絡・欠測・時間依存・事前トレンドの感度分析
       ↓
未見の実験効果予測を凍結（P04-5）
       ↓
許可された範囲のShadow評価 → RCTが可能なら外部検証
       ↓
効果・コスト・本人への害・中止を別々に評価
```

Managerの共通モデルが `p_θ(y | x,a)` を学習しても、因果的な価値 `E[Y(a)]` は識別の前提なしには出せない。**識別できない場合に`unknown`と返すことも、Managerの重要な能力**。

これにより、P05の実行エージェントには「シミュレーション予測」「因果推定」「不確実性」「安全・権限」の別々のフィールドを渡す構造を設計できる。P06ではManagerの推奨施策と強いベースラインの施策選択を公平に比較するRCTが別途必要になる。
