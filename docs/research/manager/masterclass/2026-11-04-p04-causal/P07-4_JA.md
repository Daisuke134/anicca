# P07-4｜CBT・ACT・心理的柔軟性 ― 基礎からManagerへの実装

**2026-11-05（America/Los_Angeles）｜一つのロードマップ `ROADMAP_STATUS_JA.md` に所属する学習・実装成果物。**

状態：**学習教材、非臨床の候補方策のソフトウェア実装／自動テスト。人間に対する治療・行動改善効果は未実証。** この文書は臨床心理療法をAIが提供できるという主張ではない。

## 0. 今回の学習目標（何を製品へ接続するか）

- 人の行動が「能力不足」だけでなく、*考え方、感情、行動の反復、回避、価値*の影響を受けることを正しく分類する。
- **CBT** の行動活性化・行動実験・認知再評価と、**ACT** のアクセプタンス・脱フュージョン・価値に基づく行動を同一視せず説明できる。
- COM-Bの心理的能力／自動・熟慮動機／機会と、既存のHabit Designer APIのIf–Then計画を、本人の自己選択と安全ゲートへ接続する。
- AIが患者を診断したり心理療法を自動実行したりしない。まず一般の小さな目標（学習、片付け、創作、散歩など）で**DRAFT_ONLY**か**NO_ACTION**のいずれかを返す型付きプランを実装・検査する。
- 介入が効くという主張にはランダム化等の正当な比較が必要であり、ユーザーが1回「役に立った」と言ったこととRCTでの増分効果を分ける。

## 1. CBT（認知行動療法）の基本原理

CBT = **Cognitive Behavioral Therapy / 認知行動療法**。考え、気分、行動、身体・周辺状況が相互に関係すると捉え、実際の行動と捉え方を検証する。NICE NG222（2022年公表、2026年1月レビュー）には臨床的なCBT/BAを適切な専門家の支援とともに位置づける記述がある。これは非臨床AIが自律的に治療してよいという許諾ではない。

### 例：勉強を始めようとして先延ばしする

状況：難しい論文を開いた瞬間に「理解できるはずがない」と考える。感情：不安。行動：通知アプリを開く。結果：短期的には安心、長期的には課題未着手。

- **自動思考（automatic thought）**：素早く浮かぶ評価。「自分には理解できない」。
- **認知再評価（cognitive reappraisal）**：思考を事実と同一視せず、反証や別の解釈を検討する。「最初の1段落は読めるか」を確かめる。
- **行動実験（behavioral experiment）**：一定の行動を試し、予測と結果を照合する。たとえば1分だけ見出しを読む。これは本来のCBTの一部であり、Managerの一般的プラン機能は治療を意味しない。
- **行動活性化（BA; Behavioral Activation）**：価値や成果に関係する活動を実生活へ戻す技法。NICEは抑うつの治療として専門家によるBAを紹介する。一般の習慣デザインに似ていても、臨床的BAを名乗らない。
- **回避・負の強化**：先延ばしによって不快な感覚がすぐ軽減すると、その回避が強化されうる。短期的な安心と長期的な目標達成を別に測る。

CBTの誤解：単に「ポジティブに考える」ことではない。行動・状況・証拠を含む反復的な学習である。

## 2. ACT（Acceptance and Commitment Therapy）の基本原理

ACT = **Acceptance and Commitment Therapy / アクセプタンス＆コミットメント・セラピー**。狙う中心概念は**心理的柔軟性（psychological flexibility）**。不快な思考・感情が現れても、それを即座に除去することだけに縛られず、今の文脈で本人が選んだ価値に沿った行動を柔軟に取れる能力を指す。ACBS公式解説およびAPA書籍の説明では6つのプロセスを整理する。

| ACTの六つのプロセス | 日本語の意味 | 毎日の一般的な非臨床例 |
|---|---|---|
| **Acceptance** | 不快な体験を過度に抑え込まず、ありのまま扱う態度 | 「嫌だ」という気持ちを消すことを達成条件にしない |
| **Cognitive defusion** | 思考を事実や命令として盲従しない | 「失敗する」という考えが浮かんだ、と気づく |
| **Contact with the present moment** | 注意を現在の状況へ戻す | 目の前の文章や呼吸に気づく |
| **Self-as-context** | 思考・感情・役割を観察する柔軟な視点 | 「不安という経験がある」ことと「自分は不安そのもの」を区別する |
| **Values** | その人が自分で選ぶ、行動の方向やあり方 | 誠実さ、学習、家族、健康への関心 |
| **Committed action** | 価値に沿って、必要に応じて修正できる具体的な行動 | 夕食後1分だけ自分で選んだ本を開く |

### Values と Goals の違い

- **価値（Values）**は継続的な方向性。「学ぶ人でありたい」。
- **目標（Goal）**は観測できる具体的な達成点。「今週、論文を2本読む」。
- **小さな行動（Action）**は今、許可されている実行単位。「昼食後に1段落を読む」。

この3つを混同すると、アプリのStreakを追うこと自体が目的になり、本人の価値と矛盾する危険がある。

### CBT と ACT の違い

CBTの多くのアプローチでは思考の正確さや代替的解釈を調べる。一方、ACTでは思考を文字どおりの命令として扱わない「関わり方」の柔軟性を強調する。両者は重なりがあり、完全に対立する二派という単純化は誤り。適応、治療者、対象集団、比較群、アウトカムによって効果は変わる。

2024年のACTメカニズムのメタ分析は67研究・9,123人のデータを対象とし、心理的柔軟性の各要素と苦痛変化の関連を報告。2026年のデジタル第三世代介入（ACT・マインドフルネス等）のレビューは147試験、26,391人を対象とした。**これらの効果をManagerに自動的に転用してはならない**。異質性、対照群、持続期間、介入構成が違うためである。特に有効な治療群と比較した場合の効果は弱くなることがある。

## 3. P07-3 COM-B から P07-4 へ接続する

COM-Bの下位構成要素は、介入の不足に関する**原因仮説**を構造化する。CBTとACTは、その中で検討する可能性のある技法・過程を深く理解する材料になる。

| 問題の仮説 | COM-B | 関係する原理 | 製品で許される初期の扱い |
|---|---|---|---|
| 手順が分からない | Psychological capability | 簡単な技能練習・説明 | 具体的な情報を示す |
| 時間がない | Physical opportunity | 環境の調整 | 1分の行動を提案する**下書き** |
| 目標と本人の価値がずれている | Reflective motivation | ACT values | 本人が自分で選んだ価値を記述し、矛盾を問い直す |
| 不安なため避ける | Automatic motivation | CBTの回避概念、ACT acceptance | 自動診断しない。非臨床の小さな行動を本人の明示的選択で下書き |
| うまくいかなかった | 複数の可能性 | 柔軟性・自己調整 | NO_ACTION、休む、変更する、撤回することを失敗扱いしない |

**注意：** これは診断器でも、技法の有効性を保証するマッピングでもない。もし自傷、重度の症状、医学的助言や専門的治療が必要な文脈なら、汎用AIの習慣計画を拒否し、適切な専門的な経路へ切り替える。医療や心理療法の自動実行は今回のスコープ外。

## 4. Managerへの実装（今回の具体的なコード）

既存の `services/x402-endpoint/src/routes/habitDesigner.js` は、目標と文脈からTiny HabitsやIf–Then計画のJSONを生成する有料API（$0.01 USDC、既存OpenAI呼び出し）である。**再発明せず、その出力形を再利用する。**

新規の `products/manager/manager_core/p07_4_value_action_gate.py` が行うのは、モデルが提案した行動を本人の許可なしに実行しないための、**小さな不足部分のみ**の追加。

1. `SelfChosenGoal` で本人が選んだ価値・場所・1〜5分の行動と明示的opt-inを受け取る。
2. `planning_opt_in=False`、`revoked=True`、`available=False`、臨床・医学的文脈なら **NO_ACTION**。
3. 既存Habit Designerの `safe_t_flag` がtrue/不明なら fail closed（ただしfalseでも「安全の証明」ではない）。
4. モデルが生成した `tiny_behavior` や `implementation_intention` を信頼できる実行権限として扱わない。人が選んだ行動だけを、**DRAFT_ONLY**として表示候補にする。
5. 通知や外部操作は**ゼロ**。元のAuthorityVerifier/StateMachine/Outboxを再利用する正規実行とは別である。
6. パッケージ・実行テストで「撤回」「無断通知」「臨床利用」「危険なURL」「同意不足」を拒否できることを検証する。

### 教育用の呼び出し例

```python
from manager_core.p07_4_value_action_gate import SelfChosenGoal, plan_draft

goal = SelfChosenGoal(
    goal_id="demo-1",
    value="learning",
    tiny_action="read one paragraph",
    anchor="finishing lunch",
    location="my desk",
    domain="learning",
    self_chosen=True,
    planning_opt_in=True,
    available=True,
    duration_minutes=1,
)

draft = plan_draft(goal, existing_habit_designer_result={
    "safe_t_flag": False,
    "tiny_behavior": "model suggestion not trusted as user authorization",
})

assert draft.choice == "DRAFT_ONLY"
assert draft.external_effects == ()
assert draft.behavioral_efficacy_established is False
```

これは本人の価値を意味理解したと証明するものではなく、**本人が指定した文字列だけを安全な下書きへ変換するソフトウェア契約**にすぎない。将来、使える製品にするためにはUXで実際の本人の権限・選択を確かめ、RCT/比較データを使用して得失を独立に評価する必要がある。

## 5. 最初の製品比較実験の構成

将来の実験として、一般的な自己選択習慣を対象に、(A)通常の習慣プランと(B)本人が選んだ価値に沿う1分の下書きを比較する。適切な同意・対象・ランダム割付・倫理審査に応じて設計する。

- 主要アウトカム：ユーザーが*本人の目標*を実行した回数・日数（独立測定と自己報告を区別）。
- 副次：行動の継続、自律性、罪悪感、通知負担、活動の質、離脱。
- 安全：NO_ACTION、撤回、臨床機能を名乗らない、苦痛の増加を監視する。
- 分析：割付に基づくITT、欠測/脱落、追跡期間、必要に応じてクラスター・時間帯を考慮。
- **評価前に効果量や有意差を予測して実証済みと表現しない**。

## 7. FAQ

**Q. CBTとACTではどちらが優秀？**  
症状・対象・提供者・比較群・追跡期間に依存する。単純な万能ランキングはできない。

**Q. ACTはネガティブな感情を消す治療？**  
中心は感情の完全な消去ではなく、本人にとって価値のある行動へ柔軟に関わる能力を育むことである。

**Q. COM-BのMotivationとACTのValuesは同じ？**  
同じではない。COM-Bは動機・機会・能力という分析枠組み、ACT Valuesは本人が選ぶ行動方向に関する概念であり、階層や目的が違う。

**Q. Managerが本人の価値を自動推定して介入すれば早い？**  
本人が望まない介入の危険があるため、初版は価値・行動・タイミングを本人が選び、停止可能とする。推定は仮説であり権限ではない。

**Q. モデルの提案と実際の治療はどこで分かれる？**  
教育的説明・一般習慣の下書きと、診断・症状の治療・病状の評価は異なる。今回のManagerモジュールには医療・心理療法の実行権限を持たせない。

**Q. ソフトウェアunit testに合格したら心理的な改善を証明したことになる？**  
ならない。unit testはコードの契約の検査にすぎない。ユーザーの行動・生活の質・害を独立に比較して初めて介入の実証に近づける。

**Q. 学習の次の番号は？**
