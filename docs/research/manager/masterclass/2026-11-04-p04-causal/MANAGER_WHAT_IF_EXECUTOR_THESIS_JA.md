# Manager｜究極のWhat-if Machine × Executor 研究仮説と実証ロードマップ
更新：2026-11-04 / **研究構想と未検証仮説**。実世界での万能性や収益最大化を達成済みと主張しない。

## 一文で表す中心仮説
**人間の行動と介入後の変化を十分に正確に推定できる汎用What-ifモデルと、安全に行動を実行・検証するExecutorを統合すれば、本人のためになる製品・流通・マーケティング・生活改善の選択を反復して向上させ、従来手法より高い実測の価値と利益を生み出せる可能性がある。**

この仮説が極限まで成立した世界では、価値ある製品と大規模な流通経路を、自ら開発・実験・改善する強力な事業経営システムになり得る。**「最大／世界一／どんな投稿もバズらせる／トークン以外の費用ゼロ」は到達を証明していない将来の志向であり、実証結果ではない。** 実際の費用は推論、推論以外の計算、データ、外部API、決済、広告、物流、審査、サポート、法的責任、人の監督等を含む。

## 名前と構造
- **外向きの研究・製品構想の名称は「Manager」に統一する。** 「Life Manager」は歴史的な名称・既存リポジトリ `Daisuke134/life-manager` の経路として保持し、依存関係がある GitHub リポジトリそのものや本番APIの破壊的改名は、互換性・権限・影響調査のうえで別途行う。
- **Behavior Foundation Model**：人・文脈・歴史からあり得る反応を予測する。
- **What-if / Causal Layer**：候補介入の反実仮想、識別仮定、予測区間、介入効果を推定する。
- **Decision Policy**：価値・費用・本人の意志・害・権限を考慮して行動／非行動／確認を選ぶ。
- **Executor**：許可された範囲だけで既存ツール、Codex、Dots、アプリ、業務ワークフロー等により実行。
- **Independent Verifier**：実際の売上・利益・顧客行動・回答尺度等を、実行系とは独立の計測で確認。
- **Learning Loop**：否定的な結果、失敗、停止、介入なしを含むすべての記録から更新。

`観察 → What-if → 選択 → 許可 → 実行 → 独立検証 → 改善`。

## 売り方についての仮説
Managerそのものを企業向けに直接ライセンスすることを、最初の事業モデルの必須条件としない。Manager自身が **「ユーザーが実際に使う製品・仕事を進めるサービス・流通/マーケティングのループ」** を作り、その顧客向け価値がまず証拠になる設計を優先する。将来、企業がManagerモデルやAPIを使用することは選択肢だが、事業成長の必須前提ではない。

「ManagerというUIを買う」よりも、「Managerが既に提供する成果に価値がある」を目指す。ただし、利用者に知られないまま健康状態や個人データを利用してよい意味ではない。説明・同意・撤回・監査・停止の経路を保持する。

## 実証の三本柱

| 柱 | 達成したい価値 | 主要評価指標の候補 | 強い比較対象・独立確認 |
|---|---|---|---|
| A. 良い製品を作る | 人が実際に必要とする製品を継続して生む | 課題解決率、実利用、リテンション、支払意思、返金率、貢献利益 | 手動PM/開発、既存製品、同等リソースの開発チームとの比較 |
| B. 分配・マーケティング | 良質な製品を必要な人へ低コストで届ける | 増分到達、実際の新規獲得、CAC、LTV、粗利、純増収、継続、顧客獲得費用込みの利益 | 強い既存運用、事前固定した配信計画・予算、A/Bやgeo-lift評価 |
| C. 苦しみの軽減 | 本人の反すう・心理的負担を減らし生活機能を改善する | 事前登録した心理尺度の変化、機能、負の影響、実利用・継続、本人の望む成果 | 同意に基づく介入比較、適切な対照群、独立した評価者・臨床専門家の関与 |

**注意：** バズの回数・フォロワー数・再生回数は補助的であり、実際に必要とする顧客の継続利益や本人の便益を保証しない。Xで最大のバズるアカウントを作ることは大胆な実証目標になり得るが、プラットフォームの推薦系・ネットワーク効果・競合・時間変化があり、保証はできない。フォロワー購入・虚偽広告・自動スパムなどは証拠としない。

## 心理・精神保健の実測設計（研究候補であり臨床有効性の主張ではない）
- **反すう／反復的否定思考：** RRS（Ruminative Responses Scale）、PTQ（Perseverative Thinking Questionnaire）。PTQは診断横断的な反復的否定思考を測る15項目尺度として検証されている。
- **マインドフルネス：** FFMQ（Five Facet Mindfulness Questionnaire）。日本語短縮版を含め尺度特性は研究されているが、単一得点が「解脱」「智慧」「苦の完全終息」を意味しない。
- **抑うつ症状：** PHQ-9。症状重症度の評価に使用され、医師による診断・治療の代替ではない。
- **強迫症状：** Y-BOCS。古典的な尺度は専門家が評定することを前提とし、汎用ウェルネスアプリ単体での診断・治療を正当化しない。
- **デジタル・生体指標：** 睡眠、活動、心拍、HRVなどは補助指標。反すうや抑うつの改善をそれだけで証明しない。端末・自己報告・生体信号の一致、欠測、反応性、個人差、測定バイアスを検討する。

主要尺度・時点・主要比較・最小重要差・必要サンプル数・欠測と離脱・害・有害事象を事前定義する。症状がある個人を対象にする研究や介入には、必要な倫理審査、専門家、危機時の支援経路、明確な同意が必要。健康情報をマーケティングや個人広告の最適化へ流用しない。心理的支援をうたうなら、反応率ではなくユーザーの独立に測定した便益と害で判断する。

## 実証の「証拠階段」
1. **シミュレーターのコードが動いた**：実装・単体テスト。
2. **合成人工世界の真値を推定できた**：P04-1〜P04-6の教育用実験。
3. **実在人物・研究の未提示結果を予測できた**：time/study/person holdout、正解漏洩を監査。
4. **未知の公開RCTの介入効果を予測できた**：事前の情報で予測凍結、効果量と不確実性を採点。
5. **比較方策を独立なRCTで上回った**：同じ候補・入力・権限・予算・評価指標。
6. **現実の製品や流通が持続的に価値を作った**：売上ではなく継続・費用込み貢献利益・不利益。
7. **苦しみが本人の価値観に沿って軽減した**：独立した心理尺度、害、生活機能、再現、長期追跡。
8. **異なる製品、人、文化、時期、事業へ移植しても効果が保たれた**：外部再現、OOD、負の転移を測定。

科学的に「実証済み」と書いてよいのは、各階段を実際に通過した場合だけ。生成AIの成功例や社内デモを上の段階へ勝手に繰り上げない。

## 研究評価の数学
候補方策 `π` と baseline `π_0` の差を、同じ対象分布で

\[
\Delta V = E[U(Y^{\pi}, A^{\pi})] - E[U(Y^{\pi_0}, A^{\pi_0})]
\]

と置く。売上最大化と人の利益は必ずしも一致しないため、
`利益`、`本人への便益`、`負担・害`を1つの恣意的スカラーに潰さず、主要評価とガードレールを別々に記録する。反実仮想推定が識別不能・区間が広い場合は自律実行を見送ることも方策の一部。

## 開発・公開方針
**Open-source & Open-weight を目標とする。** コード、モデルカード、再現手順、評価ハーネス、許可可能な重み・データ由来の説明を優先的に公開する。利用者の個人データ・健康情報・同意のない記録や、第三者が権利を持つ重み・データをそのまま公開しない。実際に独自重みが生成され、権利・ライセンス・安全性・悪用リスクを審査できるまでは「重みを公開済み」と記載しない。

オープン化は科学的検証と再現性を高めるための手段であり、プライバシーと安全性を損なうことを正当化しない。

## なぜ直接販売ではなく先に結果を出すのか
購入者へ「この行動モデルはすごい」と訴える前に、まず **「Managerが選んだ戦略と実行が、比較対象より実際に価値を作った」** という検証結果を公開する。実際の製品、利益、マーケティング効率、生活機能・反すうの低下がその証拠になる。第三者が追試できることが重要。大きい主張ほど、厳しい比較と否定的結果の公開を要する。
