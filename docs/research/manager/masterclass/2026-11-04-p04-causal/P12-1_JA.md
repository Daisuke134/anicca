## 0. P12-1の問い
「自社がSOTAと言った」ではなく、「別の研究者が同じ主張を検証・反証できるか」。コードが動くこと、同じ結果を再実行できること、別の人が確認すること、別の環境へ汎化することは違う。AI同士が一致したことも独立検証ではない。

## 1. Repeatability・Reproducibility・Replicabilityの違い
| 段階 | 実施内容 | 主張できる範囲 |
|---|---|---|
| Repeatability | 同じチーム・コード・データ・seedで再実行 | 同条件の反復可能性 |
| Alternate calculation | 同じチームが別実装で検算 | 内部の異なる式による整合 |
| ACM Results Reproduced | 外部チームが著者提供のArtifactも使って主要結果を再取得 | 他者による再現 |
| ACM Results Replicated | 著者のArtifactに依存せず外部チームが再検証 | 独立追試 |

ACM Artifacts Evaluated-Functionalは文書化・完全性・実行可能性を確認、Reusableは再利用しやすさまで要求。Artifacts Availableは公的なアクセス・固有ID・ライセンスを伴う。**ACM公式Badgeは自分で勝手に名乗らない**。学問によってreproducibilityとreplicabilityの語義が入れ替わるため、独立した人・データ・コード・環境の具体条件を書かなければならない。
- https://sigsim.acm.org/conf/pads/2026/blog/artifact-evaluation/
- https://reproducibility.sigmod.org/
- https://neurips.cc/public/guides/PaperChecklist

## 2. Claim-first：論文の主張を一行ずつ凍結
「行動予測性能が高い」という不明確な主張を、第三者が検算できる以下のClaim Cardへ変換：
- claim_id、予測対象と評価単位（trial/person/study/culture/work item）
- 元データのrevision・sha256・収集時期・欠測・重複
- model_id + immutable weights revision/hash + decoding settings + parser version
- train/dev/test splitのID・作り方・人物や研究の重複検査
- metric name + direction + denominator + failure/invalid rules
- seed・反復回数・ハードウェア・依存ライブラリ版・費用
- comparator（定数予測・平均・Ridge・専門モデル・既存LLM）
- confidence interval / clustering unit / multiple testing / OOD
- source code commit hash・事前凍結時刻・再現用コマンド
- code/data/modelの異なるライセンス・データ権限・用途制限
- 利益、害、実ユーザー効果は別の結論欄に記録。

「Claim Cardを含むGit commit」と「OSF等の時刻付き事前登録」は同じではない。結果を見た後で作る文書を「pre-registered」と呼ばない。OSF Registriesは後からの登録もできるが時点の明示が必要。
https://help.osf.io/article/330-welcome-to-registrations

## 3. 正しい指標：Accuracyだけで人間の予測は測れない

### 3.1 個人の回答
NLL = -(1/N) Σ_i log pθ(a_i|x_i)。正答・不正解だけでなく、正解へ割り当てた確率を評価できる。Brier = (1/N) Σ_i (p_i-y_i)^2 は二値確率を検査する。Accuracyが高くても過信した予測は危険。Calibrationは予測確率と観測頻度が整合するかを別途確認。

### 3.2 集団分布
TVD(P,Q)=0.5 Σ_a|P(a)-Q(a)|。平均や分布の再現は個々人の選択の予測とは別。尺度の異なるTVD/NLL/売上/心理尺度を「世界共通Accuracy」という一つの数字へ合算しない。

### 3.3 因果的な介入
ATE = E[Y(1)-Y(0)] は観測条件付きの予測P(Y|A,X)だけからは一般に識別できない。真のランダム割付と配信状態は別。HeartSteps実人間データ・Manager独自モデルの比較・本人への便益RCTは別Gate。送信レシートは人の行動結果ではない。

## 4. 最も起きやすい失敗はData Leakage
同一人物が100回回答したデータを行単位ランダム75:25分割すると、train/test両側に同じ人が混ざる。人物固有の癖を記憶できるモデルは、未知人物への汎化を偽装する。研究や調査サイトに固有の刺激文が学習/評価へ重複する場合も同じ。

| 問いたい汎化 | 必須の独立単位 |
|---|---|
| 未知trial | trial + 未来漏洩禁止 |
| 未知人物 | person_id |
| 未知研究 | study_id |
| 未知文化 | culture/site/language（翻訳元も照合） |
| 未知未来 | immutable temporal cutoff |
| 未知介入 | intervention_id/刺激原文・意味的近似重複 |

GroupKFoldは同じgroupがtrain/testに入らないよう設計される。trial数が大きくても、独立した人や研究の数が小さければCIは広くなる。participant/study cluster bootstrapでは対象となる独立単位を復元抽出し、全trialをまとめて再標本化する。行単位bootstrapが常に適切だとは限らない。
https://scikit-learn.org/stable/modules/cross_validation

もう一つはLeaderboard Overfitting。最終テストの値を何度も見てハイパーパラメータを調整すれば、テストをvalidationへ変えたことになる。最終未知評価セットを守り、公開後は追加の新時期・新文化holdoutで追試する。

## 5. 実際の研究者が採用している公開方法

### 5.1 Centaur
NatureのPsych-101は160心理実験、60,092人、10,681,650選択。学習用trainはHugging Face、testはCC BY-ND 4.0のgated repository、Centaur 70B+QLoRA adapterと評価コードが公開されている。ただし「公開コードがある」ことと「だれでも無条件でtestを再配布できる」ことは違う。正式な利用権・重みのライセンス・実GPU費用・パーサー等が必要。元論文結果とManager独立再現を混同しない。
https://www.nature.com/articles/s41586-025-09215-4
https://github.com/marcelbinz/Llama-3.1-Centaur-70B

### 5.2 BehaviorBench
MITの公式評価コードはtask ID、parser、個人/分布レベルの採点、JSON、dummy smoke-testを提供。評価コードのMITは独立配布されたデータ・モデルの商用権利を保証しない。BFM-02でA/B回答パーサーが抽出できない場合はinvalid_response_rateを記録し、モデルの「理解能力0%」と断定しない。
https://github.com/umich-foreseer/behaviorbench_eval

### 5.3 Model / Dataset Cards
Model Cardには用途・不適切用途・学習設定・データ・群別評価・弱点・公平性。Dataset Card/Datasheetには収集目的・出典・同意・composition・前処理・license・保守。出典や証拠の権利を公開する。
https://huggingface.co/docs/hub/model-cards
https://huggingface.co/docs/hub/datasets-cards
https://research.google/pubs/model-cards-for-model-reporting/

### 5.4 Artifact supply chain
SHA256は「同じバイト列」を証明するが「内容が科学的に正しい」ことや「使用許諾」があることは証明しない。署名・GitHub Artifact Attestationsはbuild originを示すもので、それ自体がモデル安全性を保証するわけではない。
https://docs.github.com/en/actions/concepts/security/artifact-attestations

## 6. P12-1の再現演習：P11の合成結果を別方式で検算

参照：元P11の完全合成コード experiments/p11_1_5_research_labs.py
検算：experiments/p12_1_reproducibility_audit.py
37テスト：experiments/test_p12_1_reproducibility_audit.py
固定証拠：evidence/P12-1_REPRODUCIBILITY_AUDIT_20261107.json

### 6.1 OPEの計算を独立した式で実装
元P11評価関数を呼ばず、再実装したIPS/SNIPS/DRをmath.fsumで検算。seed=1101・2状態・2行動・2万件の**同じ架空ログ**で、生成器のOracle真値=0.435、元P11 DR≈0.4353910556、別計算法DR≈0.4353910556、最大数値差≈4.32e-14。内部検算として数値が一致したのであり、実人間の意思決定価値・独立外部研究者の結果ではない。

### 6.2 負の転移を別の推定器で評価
元P11はロジスティックの勾配降下、今回のP12はx∈{-1,+1}の各群の成功割合から直接Logitを計算（極値への平滑化あり）。相反するA/B領域でshared係数のLog Lossが専用推定より悪化することを再確認。実BFMを訓練したわけではない。

### 6.3 リーク検出
完全人工12人×3観測の行単位分割はtrain/testに同一人物を含むため拒否。study単位holdoutは通る。無断の個人データ収集や実データの権限を付与する検査ではない。

### 6.4 seed変動
10 seed×各3000件の完全合成ログでDRを再計算。seed間平均≈0.43583、標準偏差をJSONへ保存。実人間のcluster-bootstrap CIではなく、人工生成器における乱数変動の確認。

## 7. 再現手順
Python標準ライブラリのみ、外部API・Secrets・有料GPU不要。ディレクトリを experimentsへ移動し、以下を実行。

~~~bash
python3 -m unittest -v test_p11_1_5_research_labs test_p12_1_reproducibility_audit
python3 p12_1_reproducibility_audit.py --source-sha 0c236f249ac4503764770135a86e2026cd37fec9
~~~

結果にPython/OS/commit/data hashを添えて第三者が提出した場合、その結果を別途検査する。第三者による再現証拠を、この自作コード実行で代替しない。

## 8. 公開ベンチマークの受入Gate
1. 予測対象・比較相手・評価母集団・独立単位を固定。
2. 法的権利、個人情報、重み再配布権を分類。
3. Data SHA・モデルSHA・コードcommit・run settings・seedを固定。
4. person/study/time/culture/domain holdoutとdata contaminationを検査。
5. NLL/Brier/TVD/Calibration/OOD/invalid_responseを別々に採点。
6. 未観測交絡と因果介入効果の限界を明記。
7. クラスターベースの不確実性、多重探索、悪化した群も公開。
8. Model Card/Dataset Card/再実行コマンド/開発環境/ソフトテストを整備。
9. 外部の研究者が別環境で主要結果を出したことを確かめた後で第三者再現と呼ぶ。
10. ユーザーの便益と害は実際の人間研究から独立に評価。
