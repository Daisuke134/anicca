# P08-1｜JITAI（Just-in-Time Adaptive Intervention）と「介入しない」選択

*2026-11-05 · Manager ONEロードマップの学習→実装→計測→公開の一工程。独立の学習TODOではない。*

## 0. なぜ必要か：行動を予測する能力と、介入する能力は違う

ある人が午後に運動しない可能性を正確に予測できたとしても、「通知すれば運動する」「通知しても害がない」ことは分からない。介入判断には、その時点の文脈・本人が受け取りたいか・同意・過去の通知負担・科学的な効果の不確実性を考慮し、**NO_ACTION（介入しない）**を正当な出力として保持する必要がある。

JITAIは、日常生活で変化する文脈・脆弱性・介入可能性に応じて、適切な種類の支援を、適切な瞬間に、必要な場合のみ提供する介入設計（Nahum-Shani et al. 2018）。単なる時刻指定リマインダーや、ユーザーに何度も通知する手法ではない。

## 1. JITAIの基本構成

| 原語 | 日本語 | 意味とManagerの設計例 |
|---|---|---|
| Distal Outcome | 遠位アウトカム | 数か月後の本人が望む習慣・生活機能。短期の歩数と同じではない |
| Proximal Outcome | 近接アウトカム | 介入判断後30分の歩数、短時間の行動達成など |
| Decision Point | 判断時点 | 昼食後や予定の区切りなど。「判断する」ことは「通知する」ことではない |
| Intervention Options | 介入候補 | NO_ACTION、任意の小さい行動の下書き、適切に許可された支援 |
| Tailoring Variables | 適応変数 | 現在の時刻・活動・本人の希望・疲労・以前の負担など |
| Decision Rule | 判断規則 | 同意・安全→状況を評価→許可された行動だけを候補とする |

設計フロー：

```
本人が自分で選んだ目標
  ↓
判断時点：今、支援を検討する意味があるか？
  ↓
安全／同意／撤回／禁止時間帯／運転中／直近の負担
  ├─ NO_ACTION / STOP / STOP_AND_REFER
  └─ 支援候補の検討
       ↓
P07 COM-Bの「不足の仮説」、本人の価値、自己報告
       ↓
DRAFT_ONLY（外部送信なし）＋後日の適切なアウトカム計測
```

## 2. HeartStepsから学ぶ「いつ・何を」

HeartStepsは37人の分析対象、研究中の6,061介入可能な判断時点で、通知後30分の歩数について介入の有無・種類を分析したMRT。原著の平均の調整済み介入効果は約35歩（p=.06）であり、歩行を促す通知は約59歩の差が報告された。研究開始時の効果が大きく、時間とともに減衰したという結果がある（Klasnja et al., 2019）。

**重要：** 初回のManager独自再分析による+12.95歩は元のランダム化割付と同一でない補正後の配信状態 `send` を利用した**記述的な差**。ITTや因果効果ではない。元研究が分析した6,061の判断時点を無断で6,590に置き換えない。

## 3. P08-2〜5で深めること（これらも同じ製品作業）

- **P08-2 MRT/N-of-1**：実際に割り付けられた介入、配信されたか、実アウトカム、割付確率を別々に保存する。MRTは多数の判断時点のランダム化、N-of-1は特定個人での介入比較。遅延や持ち越しを考慮。
- **P08-3 Contextual Bandit**：`context -> action -> reward` の繰返しから効果を学ぶ。安全な選択肢だけに限定。事前に指定した実アウトカムと負担・害を区別し、クリック率だけに最適化しない。
- **P08-4 MDP/POMDP**：過去の介入が将来の利用者の状態や通知疲れを変えることを扱う。部分観測の信念分布を理解し、本人の未観測の「心」を断定しない。
- **P08-5 Limited Trial**：本人の同意・撤回・データ権利・独立した結果測定と有害事象監視を先に定義し、必要な倫理審査を通して限定研究を実施。ソフトテストは人間の便益を証明しない。

## 4. 実装済みのP08-1：read-only判断ゲート

`products/manager/manager_core/p08_1_jitai_decision.py` は**P07の既存モジュールを再利用**し、足りなかった「時点を判断する契約」だけを追加した。

- `DecisionPoint`：ユーザーの現地時刻（0〜1439分）、禁止時間帯、運転中か、割込み可能か、最近断ったか、通知までの経過時間、当日の予算、認証済み文脈か。
- P07-6の本人の中止・有害事象判定を**常に最優先**。禁止時間帯でも有害事象を「大丈夫」と無視しない。
- 現地の時刻の検証、深夜をまたぐQuiet hours、運転、最近断った状態、クールダウン、通知頻度の上限を設定。
- P07-4の本人が選んだ一般的な目標を`DRAFT_ONLY`として扱える。瞑想に関する自己報告は任意。提供された場合のみP07-5の観察を使う。
- 戻り値には**推論した因果効果やランダム割付は存在しない**：`assigned_action=None`、`randomization_probability=None`、`causal_effect_identified=False`、`may_send_notification=False`、`external_effects=()`。
- **これは将来の通知エンジンそのものではなく、外部の操作権限を持たない純粋関数。** 実際のユーザーへ通知する前の権限とトラッキングの試験も必要。

### 説明用コード

```python
from manager_core.p08_1_jitai_decision import DecisionPoint, evaluate_jitai_point
from manager_core.p07_4_value_action_gate import SelfChosenGoal
from manager_core.p07_6_welfare_safety import OutcomeObservation

p = DecisionPoint(
    local_minute=12*60,
    quiet_start_minute=22*60, quiet_end_minute=7*60,
    safe_to_interrupt=True, driving=False, recently_declined=False,
    available_now=True, elapsed_minutes_since_last_prompt=180,
    prompts_today=0, max_prompts_per_day=1, cooldown_minutes=120,
    is_authenticated_user_context=True,
)

g = SelfChosenGoal("demo","learning","read one paragraph",
    "finishing lunch","desk","learning",
    self_chosen=True,planning_opt_in=True,available=True,duration_minutes=1)

w = OutcomeObservation(user_consented=True,consent_revoked=False,
    self_chosen_goal=True,goal_met=False,autonomy_0to10=8,
    burden_0to10=1,distress_0to10=1)

decision = evaluate_jitai_point(point=p,goal=g,welfare=w)
assert decision.choice == "DRAFT_ONLY"
assert decision.may_send_notification is False
```

このデモは本人の実際のデータでも、介入RCTでもない。「入力の安全要件を守った下書き候補を返した」というソフトウェア検証である。本人が現在の行動目標についての新しいアウトカムをまだ測定していない場合、P07-6がNO_ACTIONとなり、介入方策の性能はまだ学習できない。

## 5. 用語集・Word List

| Term | 和訳 | 意味 |
|---|---|---|
| JITAI | 適時適応介入 | その時の状況に合わせて支援の有無と内容を決める |
| Decision point | 介入判断時点 | 判断の機会。通知送信とは別 |
| Proximal outcome | 近接アウトカム | 通知後短時間などに起きる変化 |
| Distal outcome | 遠位アウトカム | 長期的な習慣・生活機能など |
| Tailoring variable | 適応変数 | 支援の選択に用いる文脈 |
| Receptivity | 受容可能性 | その時に支援へ注意を向けられるか |
| Vulnerability | 脆弱性 | 特定の望ましくない結果が生じやすい状態 |
| Opportunity | 好機 | 望ましい行動をしやすい状態 |
| Eligibility / Availability | 介入可能性 | 安全・制度・環境上、介入の選択肢があるか |
| Quiet hours | 通知禁止時間帯 | 本人の睡眠や活動を中断しない時間帯 |
| Cooldown | 連続介入の抑制 | 短時間に支援候補を繰り返さない |
| Policy | 方策 | 状況に応じて行動を選ぶ規則・モデル |
| NO_ACTION | 何もしない | 不確実性・無権限・負担への安全な対応 |
| Propensity | 割付確率 | 過去の方策がその行動を選ぶ確率。オフライン評価に必要 |
| OPE | オフ方策評価 | 過去の割付・報酬記録から新しい方策の価値を推定する |

## 6. FAQ

**Q. JITAIはただの定時通知と何が違う？** 文脈・本人の受容可能性・介入候補・判断規則・短期/長期アウトカムを定義する。何もしない選択が必須。

**Q. 判断点が1日5回なら5回通知する？** 違う。判断点ごとに介入可能性を確認し、介入しないこともある。頻度の上限は本人の希望と評価に依存する。

**Q. 今回のテストはバンディットを学習した？** していない。P08-1はまだ固定された安全な候補選択の契約であり、探索・学習する方策ではない。

**Q. P07の安全コードは何が再利用される？** P07-4の本人が選んだ目標と小さな計画、P07-5の任意の自己報告、P07-6の害と中止の判定、P07全体のNO_ACTIONを再利用する。

**Q. 運転中の推定が不確かな場合は？** 認証されていない・不明な文脈で通知しない。推定モデルの不確実性を権限へ転換しない。

**Q. このコードを実際の人に使って効果が証明された？** いいえ。合成的な単体テストと手元のロジック検証のみ。HeartSteps/Oralyticsの既存実験を学び、製品そのものは今後独立に評価する。
