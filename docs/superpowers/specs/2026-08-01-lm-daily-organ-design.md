## 1. DAILY organ とは（1行）

**予定の時刻に電話が鳴り、家を出てから着くまで案内が続き、遅れたら相手に断りを入れる。**

| 含む | 含まない |
|---|---|
| 予定 → 移動時間の自動挿入（`[Travel]` block） | Physical organ（睡眠・運動）= platform Order 36 |
| 出発の呼び出し（T-15/10/5） | Mental organ（気分・集中）= platform Order 36 |
| 移動中の案内（乗換・出口） | Financial / Marketing organ（別 spec） |
| 遅刻検知 → 相手への連絡（承認つき） | 記事・SNS・収益 loop（別 agent の担当） |

**daily 単体で商品になる**ので、physical / mental を待たずに友達へ配る。

## 2. 実行面（誰がどこで動くか）

| 層 | 実体 | daily での役割 |
|---|---|---|
| CLOUD | `apps/life-manager/`（Railway、multi-tenant） | scheduler 60s / travel 30min / ask 20min / notify。Supabase `lm_users` `lm_wake_log` `lm_travel_log` `lm_ask_log` `lm_user_locations` |
| TELEGRAM | @LifeManagerBotbot → LM webhook | ★ 全ユーザーの日常の入口はここ ★ 通知・案内・承認・ライブ位置の受け口。slash router = `apps/life-manager/lib/slash-command.js` |
| WEB panel | `/lm` | 登録（Google login → 予定 → メール → 電話番号 → 決済）と履歴の確認。日常操作は Telegram で完結する |

**原則**: 毎日触るものは Telegram、設定と履歴だけ web。「毎日 web を開かせる」設計は失敗とみなす。

## 5. Telegram UI/UX（daily の全画面。これが完成形）

### 5.1 登録（1回だけ）

```text
 /start
   │
   ├─ 名前を聞く（チャットで直接入力）
   ├─ 予定をつなぐ           → ボタン → /lm?tg=<chat_id>（OAuth は web）
   ├─ メールをつなぐ         → ボタン → /lm?tg=<chat_id>
   ├─ 電話番号（任意）★#9★  → 未入力なら「Telegram だけで届けます」と明示
   ├─ ライブ位置を共有       → 📎 → 位置情報 → ライブ位置情報（無期限）★#11★
   └─ 支払い                 → ボタン → Stripe
        │
        ▼  🎉 「明日の朝から始めます。何もしなくていいです」
```
