# World ID 4.0 Personhood Gate — /income UBI sybil gate (rebuild)

**Date**: 2026-06-21
**Status**: in progress (replaces the classic IDKitWidget@2.4.2 build — see below)
**Why this rebuild**: E2E (World ID simulator) revealed the classic `claim-ubi` action could not
generate proofs — the Developer Portal funnels old apps to "Enable World ID 4.0" (RP registration).
verifyCloudProof + classic IDKitWidget is the OLD paradigm. The current external-web personhood flow
is World ID 4.0 (`@worldcoin/idkit-core` + RP signature + `developer.world.org/api/v4/verify/{rp_id}`).
The classic gate was rolled back (it blocked 100% of signups) — prod signups are currently ungated.

## Lesson (HARD 0.31)
Never enable a gate in production before the ACCEPT path is verified end-to-end (a real/simulator
proof → verify success → recorded). Unit tests + the reject path are NOT E2E.

## Architecture (4 components: client / backend / World App / Developer Portal)

| Step | Where | What |
|---|---|---|
| 1 | install | `@worldcoin/idkit-core` |
| 2 | Portal | Enable World ID 4.0 (Managed). Get `app_id`, `rp_id`, and `RP_SIGNING_KEY` (signer key, secret) |
| 3 | backend `rp-signature` | `signRequest({ signingKeyHex: RP_SIGNING_KEY, action })` → `{ sig, nonce, createdAt, expiresAt }`. NEVER on client; key never exposed. |
| 4 | frontend `/income` | fetch rp-signature → `IDKit.request({ app_id, action, rp_context:{ rp_id, nonce, created_at, expires_at, signature }, environment, allow_legacy_proofs:true }).preset(orbLegacy({ signal }))` → `request.connectorURI` (QR) + `request.pollUntilCompletion()` → IDKit response |
| 5 | backend `verify` | forward IDKit response AS-IS to `POST https://developer.world.org/api/v4/verify/{rp_id}` → `response.ok` = cryptographically valid |
| 6 | backend store | extract `responses[0].nullifier`; atomic UNIQUE(nullifier, action) insert → dedupe (one human = one claim) |

## IDKit 4.0 response shape
```
{ protocol_version, nonce, action, environment,
  responses: [ { identifier, signal_hash, proof, merkle_root, nullifier } ] }
```

## Our wiring (netlify functions + Supabase, mirrors the rolled-back design but 4.0-correct)
- `netlify/functions/rp-signature.js` — POST {action} → signRequest with RP_SIGNING_KEY → {sig,nonce,created_at,expires_at}. Fail-closed if key missing.
- `netlify/functions/_lib/worldid4.js` — shared: `verifyV4(idkitResponse, rpId)` (forward to v4/verify/{rp_id}, return {ok}), `extractNullifier(idkitResponse)`, `claimNullifier(insert, nullifier, action)` atomic. Pure + injectable for tests.
- `income-signup.js` — authoritative gate: when WORLDCOIN_RP_ID set, require `body.idkitResponse`, verifyV4 → on ok, atomic-claim nullifier (UNIQUE) → record recipient. Reject (no record) on fail/dup. Fail-closed.
- `/income/page.tsx` — replace classic IDKitWidget with idkit-core flow: button → fetch rp-signature → IDKit.request → show QR (connectorURI) → pollUntilCompletion → on success setVerified + carry idkitResponse → send in income-signup body. Reset on email change (signal binding). taste-harmonized.
- Supabase `personhood_nullifiers` (exists): UNIQUE(nullifier_hash, action). Store the nullifier hex (lowercased) — docs recommend NUMERIC(78,0) decimal; we keep text but normalize to avoid casing dupes.

## Signal binding
signal = email (lowercased). Enforced on both `IDKit.request(...preset(orbLegacy({signal})))` AND the
server (the v4 verify checks signal_hash). Reset verified+response on email change.
