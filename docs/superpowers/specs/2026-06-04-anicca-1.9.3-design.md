## 1. Overview (What & Why)

### What
Anicca iOS 1.9.3 を 1 リリースで App Store に提出。 1.9.2 の **IM-feed swipe UX を ZERO-TOUCH で維持** したまま、 6 layer を追加 (1.9.1 で予定だった 7 機能から ③ billing banner を削除):

| # | layer | 種類 | 実装位置 | 可視性 |
|---|-------|------|---------|--------|
| ① | iOS PushTokenService.register 修復 | iOS hotfix | AppDelegate.didFinishLaunching + PushTokenService.register | invisible |
| ② | backend affirmation sender source 統一 | backend verify | apps/api (既 main land、 Railway deploy 確認) | invisible |
| ④ | cold-start race fix (pendingQuoteId) | iOS | AppState + AppDelegate.didReceive + FeedRootView.onAppear | invisible (通知タップ時) |
| ⑤ | JA 12 件 humanize | content | apps/api/.../catalog/ja.json | invisible (text content) |
| ⑥ | newsletter = 既存「Daily Anicca Letter」接続 | iOS UI | SettingsSheet Section + 既存 lead-magnet endpoint | visible (Settings 内) |
| ⑦ | feedback form | iOS UI + Netlify | SettingsSheet Section + FeedbackFormView + 新 Netlify function | visible (Settings 内) |

★ **削除した layer**: ③ billing-issue banner (Dais「クソすぎる」)。 FeedRootView の ZStack overlay 追加 = 不要 → IM-feed 破壊 risk が消滅。

### Why

**1.9.1 が live で IM-feed UX を破壊した教訓 (Dais 2026-06-04 確認):**
- 1.9.1 build 366 = iam-feed branch HEAD ベースで、 swipe フィードが旧 UX に逆戻りしていた
- 修正: 1.9.2 で 1.9.0 IM-feed source (fe25e111) を rebuild → WAITING_FOR_REVIEW 提出済 (build 367)
- 1.9.3 の使命: 1.9.1 でやりたかった機能を、 IM-feed swipe 体験を **1 文字も壊さず** に追加

**⑥ newsletter の方向転換 (調査で判明、 Dais 指示):**
- 「アニッチャが毎日オリジナルの手紙を書いて送る」べき (ランダム affirmation メールは飽きる/間違い)
- ★ 既存システムが稼働中 ★ = aniccaai.com/letter「Daily Anicca Letter」($9.99/月、 365 通、 毎朝 ~150 words)
- 仕組み: Supabase `subscribers` テーブル + `daily-letter-sender` cron (06:13 JST、 Resend Batch、 day_offset drip) + `weekly-fresh-letter` cron (gpt-5.4-mini が今週の news×無常 で fresh letter 生成、 飽き防止) + `letter-bank-builder` (365 通 bank 生成)
- ★ iOS は web と同じ `aniccaai.com/.netlify/functions/lead-magnet` を叩くだけ ★ で既存システムに乗る
- 私が前回作った Railway `newsletter.js` (random affirmation) は全廃

## 3. As-Is / To-Be

### ① iOS PushTokenService.register 修復

| | As-Is (1.9.0/1.9.2) | To-Be (1.9.3) |
|---|---------------------|----------------|
| didFinishLaunching | `await registerForRemoteIfAuthorized()` (`if authorized` gate) | `await registerForRemoteNotifications()` 無条件 + pending flag retry |
| applicationDidBecomeActive | `registerForRemoteIfAuthorized()` | `registerForRemoteNotifications()` 無条件 |
| PushTokenService.register | 単発 POST、 retry なし | `postOnce` を 3 retry (delays [0, 1s, 2s])、 全失敗で `pushTokenRegistrationPending` flag |

### ② backend source 統一 (verify のみ)

| | As-Is | To-Be |
|---|-------|-------|
| main affirmation sender | 既 land (title=アニッチャ/body=affirmation/quoteId) | 変化なし — Railway 稼働確認 (Dais: 36分前通知 OK) |

### ④ Cold-start race fix (★ pull-only 方式 = reviewer C-2 反映)

★ **設計核心 (C-2)**: FeedRootView に `@ObservedObject appState` を **追加しない**。 追加すると pendingQuoteId 変化で body 全体 (VerticalPager 含む) が再描画され、 1.9.1 型の挙動変化 risk。 代わりに `.onAppear` 内で `AppState.shared.consumePendingQuoteId()` を **一度だけ pull** する (購読しない)。 これで body の再描画グラフを一切変えない。

| | As-Is | To-Be |
|---|-------|-------|
| AppState | pendingQuoteId なし | `var pendingQuoteId: String? = nil` (★ `@Published` **不要** — FeedRootView は購読せず pull するだけ) + `consumePendingQuoteId() -> String? { defer { pendingQuoteId = nil }; return pendingQuoteId }` (@MainActor) |
| AppDelegate.didReceive | aniccaScrollToQuote post のみ | post 維持 (warm path) + `Task { @MainActor in AppState.shared.pendingQuoteId = quoteId }` (cold-launch queue) |
| AppDelegate.didFinishLaunching | — | `#if DEBUG` launch arg/env parse (PENDING_QUOTE_ID_ON_LAUNCH) for Maestro |
| FeedRootView.onAppear | quotes 初期化のみ (L50-54) | 末尾に `if let qid = AppState.shared.consumePendingQuoteId(), let idx = quotes.firstIndex(where: {$0.id == qid}) { withAnimation { currentIndex = idx } }` 追加 (★ `AppState.shared` を直接 pull、 プロパティ購読なし)。 ★ 既存 quotes 初期化 不変 ★ |
| FeedRootView の body プロパティ | appState 参照なし | ★ **変更なし** — `@ObservedObject` も `@EnvironmentObject` も追加しない。 onAppear クロージャ内で `AppState.shared` を呼ぶだけ (再描画グラフ不変) |

## 5. Boundaries (Out of Scope) — ★ ZERO-TOUCH 原則 ★

| Out / 禁止 | 理由 |
|-----------|------|
| **`ContentRouterView` (ContentView.swift) の routing 変更** | 1.9.1 が壊した最有力候補 |
| **`aniccaiosApp.swift` の WindowGroup / onOpenURL 変更** | エントリポイント不変 |

| **OnboardingFlowView 変更** | onboarding 不変 |
| **③ billing-issue banner** | Dais「クソすぎる」→ 実装しない (FeedRootView ZStack overlay 追加 = 不要) |
| Newsletter の独自配信ロジック (Railway random affirmation) | 既存「Daily Anicca Letter」に乗るので不要、 全廃 |
| iOS streak 機能 | NEVER (IAM benchmark で retention 殺す) |
| Android | 据置 |

## 9. Risks & Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
