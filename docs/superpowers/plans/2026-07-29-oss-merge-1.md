# OSS-MERGE-1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the canonical `Daisuke134/life-manager` checkout the only required source tree for the Life Manager product, with portable install/test/eval commands and no private runtime, local-folder, submodule, or generated-artifact dependency.

**Architecture:** A repository-level verifier is the executable boundary: it reads the Git index, source manifest, active runtime files, installer output, and clean-clone result. Reusable code is copied from pinned source commits into canonical paths with provenance; private state and product-specific personal configuration stay external. Public third-party dependencies use pinned package/source downloads with checksum and license metadata rather than Git submodules.

**Tech Stack:** Git, Node.js 22 test runner, Python 3.11 stdlib, Bash, npm `ci`, GitHub Actions, SHA-256 manifests.

## Global Constraints

- Existing Mac loops remain loaded and unchanged throughout this atomic.
- Canonical repository and push target are `https://github.com/Daisuke134/life-manager`.
- Required Life Manager code may not resolve through `~/profitable-claude`, `~/anicca`, `~/.openclaw`, `/Users/anicca`, a private Git URL, a Git submodule, or a symlink escaping the repository root.
- `anicca-dais` secrets, identity, logs, state, generated media, and credentials remain external inputs and are never copied.
- Anicca/Honne product-specific code and personal product data are not fixed public Life Manager capabilities.
- New behavior and bug fixes use RED → GREEN → REFACTOR.
- Completion requires a clean clone at the branch commit, `npm ci`, focused tests, full tests, all evals, installer verification, and repository verifier PASS.
- Sources: npm documents `npm ci` as the clean, frozen install for automated environments (`https://docs.npmjs.com/cli/v11/commands/npm-ci`); Git documents submodules as embedded separate repositories (`https://git-scm.com/book/en/v2/Git-Tools-Submodules`, Japanese: `https://git-scm.com/book/ja/v2/Git-のさまざまなツール-サブモジュール`); GitHub documents scanning the entire Git history for committed credentials (`https://docs.github.com/en/code-security/secret-scanning/introduction/about-secret-scanning`).
