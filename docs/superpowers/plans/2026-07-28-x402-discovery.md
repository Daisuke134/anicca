# x402 External Discovery Implementation Plan

**Goal:** The production `x402-agents` Railway origin publishes a complete OpenAPI discovery contract for all nine paid routes, passes the official AgentCash/x402scan discovery and endpoint audits, and becomes externally searchable without changing payment settlement or stopping any existing loop.

**Architecture:** Extract the paid-route catalog into one module shared by the payment middleware and generated OpenAPI document. Serve `/openapi.json` before the fail-closed paid-route guard. Each operation carries an exact input schema, a decimal USD `x-payment-info` block, a `402` response, realistic output metadata, and contact/guidance fields. Keep runtime payment configuration authoritative and add contract tests that fail on route, price, method, or schema drift.

**Primary-source basis:**

- x402scan integration spec: “OpenAPI is the canonical discovery contract. Publish your spec at /openapi.json.” It also requires each payable operation to include `x-payment-info`, `protocols: [{"x402": {}}]`, a `402` response, and an input schema.
  https://github.com/Merit-Systems/x402scan/blob/main/apps/scan/src/app/(app)/(home)/integration-spec/page.tsx
- x402scan registry source: “Endpoints missing an input schema are reported as skipped.”
  https://github.com/Merit-Systems/x402scan/blob/main/apps/scan/src/lib/discovery/register-origin.ts
- Coinbase Bazaar: sellers must register `bazaarResourceServerExtension`, attach `declareDiscoveryExtension()`, and complete a CDP-facilitated settlement; metadata should contain clear examples, documented inputs, semantic descriptions, and schema-valid extensions.
  https://docs.cdp.coinbase.com/x402/bazaar

The existing user instruction to finish the remaining earning TODOs authorizes publishing this specific already-live product origin after its deployed audit passes. No self-payment may be counted as revenue.
