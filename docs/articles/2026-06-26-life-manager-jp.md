# 出発の10分前に電話してくる予定管理AI ― Life Manager を作って動かした記録

## 最初に：この記事は何か

- **Life Manager とは**：Google カレンダーを読み、予定の前に「移動時間」を勝手に埋め、出発の10分前と5分前にあなたの携帯へ電話をかけて「そろそろ出て」と声で急かす AI。場所が分からない予定は Telegram かメールで聞いてくる。スマホアプリは無い。電話とメッセージだけで動く。
- **やったこと**：この AI を実際に組んで、自分の番号で電話を受けるところまで動かした。声で起こす部分、移動時間の自動登録、場所を埋める部分まで、一通り通した。
- **結果**：出発前の電話は本物の携帯に着信した（Gemini Live の音声 Charon が話す）。AI が場所を判断して実カレンダーに自動記入する部分も動いた。聞く必要がある時は Telegram で質問して返信を受ける経路が本番で動いている。メール経路は送信を実送信で確認したが、返信を受ける部分はまだ単体試験まで（本番のメール受信は未接続）。料金は月20ドル。
- **おすすめする人**：寝坊・遅刻・連絡漏れが多い人。アプリを開く習慣が続かない人。予定はあるのに「家を出る時刻」をいつも逃す人。
- **おすすめしない人**：通知アプリで十分間に合っている人。電話で急かされるのが嫌な人。カレンダーをそもそも使わない人。

## アプリではなく、電話がかかってくる

リマインダーアプリの問題は、通知が「予定の時刻」に鳴ることだ。10時の会議なら10時に鳴る。だが本当に必要なのは「家を出る時刻」のアラートで、会議が30分かかる場所なら9時20分に動き出さないと間に合わない。多くのアプリはこの「出発時刻」を計算しない。

Life Manager は逆から考える。予定の場所までの移動時間を調べ、出発時刻を「予定開始 − 移動 − 余裕5分」で割り出し、そこから10分前・5分前に電話をかける。通知ではなく、鳴る着信音と声で「今すぐ出て」と言う。無視しづらい。

## 何をする AI なのか

やることは4つに分かれる。

```
┌─────────────────────────────────────────────┐
│ Life Manager の4つの仕事                       │
├─────────────────────────────────────────────┤
│ ① 移動ブロック  予定の前に [移動] 枠を自動登録    │
│ ② 出発前コール  T-10分 / T-5分 に電話（声で急かす）│
│ ③ 場所を聞く    場所未定 → Telegram/メールで質問  │
│ ④ 遅刻連絡      間に合わない → 相手に連絡案を下書き │
└─────────────────────────────────────────────┘
```

①は毎朝カレンダーを読み、まだ移動枠が無い予定にだけ枠を足す（オンラインや移動の要らない予定には足さない）。②は出発時刻が近づいた予定に電話する。③は AI が「これはオンライン会議か、対面か」を判断し、対面なのに住所が無ければ本人に聞く。④は移動時間的に間に合わないと判断したら、相手への連絡文を下書きして本人の承認後に送る。

## 似たものと、何が違うか

予定管理を「自動化」する道具はいくつもある。違いは「どこまで人が手を動かすか」だ。

| 道具 | 何をする | 出発時刻を計算 | 電話で起こす |
|---|---|---|---|
| 標準のカレンダー通知 | 予定時刻に通知 | しない | しない |
| 移動時間アプリ（経路系） | 経路と所要時間を表示 | 見せるだけ | しない |
| AIスケジューラ（予定調整系） | 空き時間の調整・予約 | しない | しない |
| **Life Manager** | 移動枠を書き込み・出発前に電話 | する（予定−移動−余裕） | する（T-10/T-5、声） |

経路アプリは「30分かかります」と見せてくれるが、その30分前に動けと電話まではしない。Life Manager は計算した出発時刻を行動のトリガーにして、電話という無視しづらい手段で介入する。そこが他と違う。

## どう動いているか（中身）

中身は外部サービスの組み合わせで、判断が要る部分だけ AI に任せている。

**カレンダーの読み書き**は Composio（コンポジオ）という連携サービス経由で Google カレンダーにつなぐ。ユーザーは自分の Google アカウントで一度許可するだけで、以降は移動枠の追加や場所の書き戻しが自動で走る。

**電話**は Telnyx（テルニクス）という通話インフラと、Google の Gemini Live（音声を直接生成する AI）をつないでいる。出発時刻が来ると番号に発信し、Gemini Live の音声プリセット Charon が「次の予定の10分前です。そろそろ動いて」と話す。10分前は穏やか、5分前はきつめ、と緊急度を上げる。これは固定のルールではなく、緊急度ラベルを渡して声色を変えている。

**場所の判断**だけは正規表現やキーワードではなく、AI に決めさせている。「藤井さんと電話」ならオンライン、「渋谷で打合せ」なら対面で住所が要る、という区別を、AI が予定のタイトルと場所欄から判断する。対面で住所が分からなければ、本人に質問を送る。一度教われば記憶し、次の同じ予定では聞かない。

ここで一つ正直に書くと、Life Manager は「予定の前に必ず電話する」を保証する仕組みではなく、毎分カレンダーを見て出発時刻の窓に入った予定を拾う方式だ。窓は数分の幅があり、重複しないよう一度かけた予定は記録して二重発信を防ぐ。完璧な時刻保証ではなく、実用上の「ほぼ確実に間に合う」設計になっている。

## 質問と返信を、どのチャネルで受けるか

「場所を聞く」には、聞く相手の連絡先が要る。Life Manager は Telegram をつないだ人には Telegram で聞き、返信もそこで受ける。Web から登録した人にはメールで聞く設計になっている。

メールの受け方には工夫がある。ユーザーの Gmail を読むのではなく、こちらのドメイン（aniccaai.com）から質問を送り、返信先を `reply+<トークン>@reply.aniccaai.com` にしておく。ユーザーが返信すると、それはユーザーの Gmail ではなく**こちらの受信箱**に届く。だからユーザーの Gmail を読む権限は一切要らない。

なぜこれが大事か。Gmail を「読む」権限は Google の制限が厳しく、外部公開アプリは年単位のセキュリティ審査（CASA）が必要で、費用も時間もかかる。さらに連携業者の多くはユーザー1人あたりの月額課金になり、利用者が増えるほどコストが膨らむ。**読まずに、自分のドメインで返信を受ける**設計なら、その審査も人数比例の課金も避けられる。返信に埋め込んだトークンで「誰の、どの予定への返信か」を識別し、その予定の場所欄に書き戻す。トークンは推測できない128ビットのランダムな文字列で、対応する予定は手元の台帳で引く（暗号署名ではなく、長さと乱数だけで当て推量を防ぐ）。

## 実際に組んで、動かした

組み立ては、外部サービスをつなぎ、判断を AI に渡し、端から端まで通すという順で進めた。

- カレンダー連携（Composio）でテスト用の予定を作り、移動枠が自動で入ることを確認した。
- 出発時刻が近い予定に発信し、実際の携帯に着信して Charon の声が流れることを確認した。
- AI が場所を判断して実カレンダーの場所欄に自動記入する部分は、本物のカレンダーで動いた。聞く必要がある場合の Telegram での質問と返信の経路も本番で動いている。
- メールの送信は本物の送信で確認した（こちらのドメインから実際に届いた）。返信を受ける部分は、推測不能トークンで「誰の予定か」を引き当て、重複返信では二重に書き込まないことを単体試験で確かめた（本番のメール受信の接続はこれから）。

途中で一つ詰まったのは、メールの返信先アドレスが長すぎてメール規格の上限（ローカル部64文字）を超え、送信が弾かれたことだ。最初は本人IDと予定IDをそのまま埋め込んでいたが、これだと長くなる。短いランダムなトークンに切り替え、トークンと予定の対応は手元の台帳で引く方式にして解決した。

## で、使えるのか

正直な評価から書く。

**おすすめする人**：
- 寝坊や遅刻が常習で、通知では起きられない人。電話の着信なら無視しづらい。
- 「予定は分かっているのに家を出る時刻を逃す」人。出発時刻の逆算が一番の価値。
- アプリを開く習慣が続かない人。開くものが無く、電話とメッセージだけで完結する。

**おすすめしない人**：
- 既存の通知で間に合っている人。わざわざ電話で起こされる必要は無い。
- 電話で急かされること自体がストレスな人。
- カレンダーを使わない人。読む対象が無ければ何も起きない。

料金は月20ドル。電話・移動計算・場所の記憶まで含む。アプリのダウンロードは無い。Telegram で @LifeManagerBotbot に話しかけて、名前・カレンダー・電話番号を登録すれば始まる。

補足：なぜ Gmail を読まないのか（少し専門的な人向け）

Gmail を読む権限（gmail.readonly など）は Google の「制限付きスコープ」に分類され、外部の一般ユーザーに公開するアプリは、毎年のセキュリティ審査（CASA、第三者監査）を通す必要がある。費用は数千〜数万ドル規模、期間も数週間から数か月。一方「送る」だけ（gmail.send）は「機微スコープ」で、軽い審査で済み監査は不要。Life Manager は読みを完全に避け、自分のドメインで返信を受けることで、この審査も、ユーザー数に比例する連携業者の課金も回避している。返信先に埋め込むトークンは128ビットのランダムな値で、当て推量で他人の予定に書き込むことはできない。
