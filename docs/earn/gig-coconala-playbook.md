## 2. コンポーネント別・実行可能な型

### A. プロフィール（アイコン・表示名・キャッチコピー・自己紹介・ポートフォリオ）

- **自己紹介文は上限文字数（1,000字）まで書き切る。100字→1,000字に増やしたら受注が伸びた。** 長文でも「興味のある人しか読まないので長文でも読まれる」。5〜6時間かけて書き直した。（出典: ec.minikuru.co.jp）
- **自己紹介は「経歴の羅列」ではなく「あなたの何を解決できるか」を先に書く。** 例:「元SIerで業務システムを10本以上開発」より「請求書作成の手作業、自動化できます」の方が刺さる。（出典: devsideup.com）
- **プロフィール写真は、顔出しが苦手でもイラストアイコンより実写に近い雰囲気の方が信頼されやすい。** 顔出しNGならプロ品質のアイコンを外注（1,000〜3,000円）してでも整える。（出典: devsideup.com, shikaku-side.com）
- **キャッチコピーには「〇〇専門」「〇〇件の実績」など具体的な数字・専門性を入れる。**（出典: shikaku-side.com）
- **自己紹介文の推奨構成**: 自己紹介（名前・職業・経歴）→ 得意分野・強み → 実績・経験（具体的な数字で。「制作実績50件以上」のように） → サービスへの想い → 対応可能な範囲。（出典: shikaku-side.com, creators-academy.co.jp）
- **プロフィール項目一式**: 簡単な自己紹介／経歴や実績／対応可能な作業／対応可能な時間帯／意気込み／（該当スキルなら）料金表・ポートフォリオ。（出典: creators-academy.co.jp）
- **ポートフォリオは「言葉」より「証拠」。** 過去の作品・実績を画像やリンクで掲載し、文章で「安心・信頼」と書くよりも実物で感じさせる方が効く。（出典: ec.minikuru.co.jp, shikaku-side.com, creators-academy.co.jp）
- **実物サンプルをGitHub等で無料公開し、発注前の安心材料にする実例あり。** 「30,000円で何が届くのか」を具体的に見せるため、各サービスの成果物サンプル＋実行可能コードをリポジトリ化し、出品ページ・プロフィールから誘導。ポートフォリオリンク（`show-smartwork.dev`）もプロフィールに明記。（出典: github.com/SHOW-17/ai-automation-samples — これは唯一「AIエンジニアがAI生成物をポートフォリオとして出す」実例）
- **プロフィール閲覧後の購入率は、資格・実績の前面提示で大幅に向上する（体験談ベース、数値の裏取りなし）。**（出典: shikaku-side.com）

### B. 出品（タイトルの型・価格設定・パッケージ構成・サムネ・説明文構成）

- **タイトルは検索キーワードを左（前半）に入れる。** 検索候補に出るキーワードを意識し、狙ったキーワードほど左に配置すると上位表示されやすい（体験談）。キャッチコピー内の語も検索にヒットする。キーワードを詰め込みすぎると各キーワードの重みが分散し逆効果。（出典: ec.minikuru.co.jp）
- **タイトルは「作業」でなく「悩みの解決/ベネフィット」を書く。** 悪い例:「記事を書きます」／良い例:「SEO対策済み！不動産・金融記事を5,000円で執筆します」。「React で〇〇を作ります」より「予約管理システムを月1万円で作ります」の方が刺さる。（出典: shikaku-side.com, devsideup.com）
- **タイトルと冒頭3行が最重要。** 多くのユーザーは冒頭だけ見て続きを読むか判断するため、メリットを最初の3行に配置する。（出典: creators-academy.co.jp）
- **説明文の推奨構成**（複数ソースで一致）:
  - devsideup: 悩みの提示（冒頭2〜3行）→ 具体的な納品物と作業範囲 → 納期の目安 → 追加オプション（急ぎ対応・保守など）
  - shikaku-side: サービス概要 → こんな方におすすめ → サービス内容（具体的な納品物）→ 購入後の流れ → 注意事項・対応できないこと
  - listing_playbook（我々の既存値）とほぼ一致: 対象→内容→納品物→流れ→料金→注意
- **本文は記号・箇条書きで区切り、一行50字程度に収める。** 文章の丁寧さが「出品者の人間性」として伝わり信頼につながる。（出典: ec.minikuru.co.jp）
- **価格は複数プラン（松竹梅/3段階）にすると平均単価が上がる。** 「1プランのみ→3プラン化」で平均単価が1.5倍になった実例。安いプランで間口を広げ、高いプランに保守・追加機能を乗せる。（出典: devsideup.com, shikaku-side.com, 我々の`plan_tier_template`と一致）
- **実績ゼロ時は低価格（1,000〜3,000円）で10〜20件の実績を最優先で積む。** 実績が貯まると検索順位・購入率が大幅に上がる。値上げのタイミングの目安: 実績10件到達で1,000→3,000円、実績20件で3,000→5,000円、実績50件で5,000→1万円。（出典: shikaku-side.com）
- **カテゴリ別相場（2026年、ソース: creators-academy.co.jp, shikaku-side.com。数値は各記事の実測/調査ベース）**:
  - イラスト・アイコン: 3,000〜15,000円
  - Webサイト/LP制作: 30,000〜300,000円（高単価だが月1〜2件受注が目安）
  - プログラミング/IT: 小規模5,000〜20,000円、システム開発20,000〜200,000円
  - 動画編集: 5,000〜300,000円（幅が大きい）
  - ライティング: 1文字1円前後スタート、実績で2〜3円に
  - SNS運用代行: アドバイス1,500〜10,000円、運用代行月25,000〜100,000円（継続契約になりやすい）
  - 占い・鑑定: 電話100〜400円/分、メール500〜5,000円/通
  - ビジネス相談/コンサル: 5,000〜100,000円
  - データ入力/文字起こし: 1,500〜3,000円（低単価だがスキル不要）
- **サムネイル画像は文字入れ必須で有料素材を使う。** 1枚目は全て有料素材（PIXTA等）に変更した実例。「相談人数1,000人突破」のような実績を画像に文字入れしてアピール。顔写真NGならオリジナルイラストの顔でも良いが、印象に残らないのはNG。（出典: ec.minikuru.co.jp。我々の`listing_playbook`の「サムネイルは文字入れ必須」と一致）
- **複数サービス・複数カテゴリで出品して「窓口」を広げる。** 同じキーワード群でも切り口を変えた複数サービスを出品し、検索網羅性を上げる。カテゴリを分けるとレコメンド表示（同カテゴリ・同価格帯が並ぶ枠）にも載りやすい。（出典: ec.minikuru.co.jp。我々の`listing_rotation_rule`と一致）
- **ココナラのアルゴリズムが重視すると言われる4要素**: クリック率（CTR、サムネ/タイトル）、購入率（CVR、説明文のわかりやすさ）、満足度（レビュー評価）、情報の鮮度（定期的な出品内容の更新）。（出典: creators-academy.co.jp。我々の`listing_playbook`の「週1回更新」と一致）
- **AI副業カテゴリのニッチ選定実例（サービス階層設計）**: 「自動化相談 ¥3,300」を入口にして、そこから「Python自動化 ¥15,000〜」「AI情報発信自動化 ¥22,000」「AI記事自動生成 ¥15,000」に振り分け、最終的に「Claude Code開発代行 ¥30,000〜」に集約する階層構造。安価な相談サービスを漏斗の入口にする設計。（出典: github.com/SHOW-17/ai-automation-samples）

### C. 提案/応募（提案文の型・返信速度・見積の出し方）

- **返信は半日以内（devsideup）〜24時間以内・できれば6時間以内（shikaku-side）を死守。** 迅速な返信自体が信頼の印象を作る。（出典: devsideup.com, shikaku-side.com）
- **メッセージ対応では要件を箇条書きで整理して返信し、「〇〇という理解で合っていますか？」と確認を挟む。** 認識ズレの事前防止。（出典: devsideup.com）
- **見積もり時点で「対応範囲」を明記する。** 曖昧にすると後から無償対応を要求されトラブルになる。（出典: devsideup.com, creators-academy.co.jp）
- **ヒアリングは着手前に不明点をゼロにする。** 具体的なイメージ画像や独自ヒアリングシートを使う（例: イラストなら「使用用途/性別/髪型/髪色/服装/背景色/納品形式/その他要望」のテンプレ）。（出典: creators-academy.co.jp）
- 我々の既存`proposal_playbook`（掲載直後30分以内の応募最優先・5段構成の提案文・実績ゼロ時は相場の約80%提示）は上記ソース群と整合しており、追加の反証は見つからなかった。

### D. 評価と実績の作り方（最初の1件・レビュー集め・ランク上げ）

- **最初の10件は友人・知人や過去の取引先に格安で依頼し、レビューを先に集める。**「同居人は購入不可」など自作自演対策があるため、身内でも正規の別注文として扱われる必要がある。（出典: shikaku-side.com, ec.minikuru.co.jp — ただし ec.minikuru.co.jp は「同一住所ユーザーは注文できなかった」と明記しており自作自演は不可と釘を刺している）
- **プラチナランクまでは時給を度外視し、最低価格に設定してレビュー獲得を最優先する。** 実例: 電話相談1分100円、メッセージ相談500円で2ヶ月・約5万円（時給換算270円）。「この初期段階が一番難易度が高い、プラチナ到達で初めてスタート地点」。（出典: ec.minikuru.co.jp）
- **レビューは全件に返信し丁寧に対応する（必須）。** プラチナ到達までの下積み期間は手間を惜しまない。（出典: ec.minikuru.co.jp）
- **納品後に評価を依頼するメッセージを送るとレビュー獲得率が上がる。** 良いレビューが3件を超えたあたりから検索順位が上がり問い合わせが増えたという体験談。（出典: devsideup.com）
- **評価4.8以上を維持しないと売れにくい。** 迅速なレスポンス・丁寧なコミュニケーション・納期厳守・高クオリティ・アフターフォローの5点で高評価を作る。実例ではリピーター率30%以上を達成。（出典: shikaku-side.com）
- **収入ロードマップの目安（体験談ベース）**: 開始〜3ヶ月＝実績作り期（月0〜5,000円）／3ヶ月〜半年＝成長期（月1〜3万円）／半年以降＝安定期（月5〜10万円以上）。（出典: creators-academy.co.jp）

### E. ニッチ選定（今どのカテゴリが儲かるか・AI系の需要）

- **需要が高い7ジャンル（複数ソース一致）**: イラスト・デザイン／Webサイト制作・LP／ライティング・記事作成／動画編集／占い・スピリチュアル／ビジネスサポート（資料作成・Excel・データ入力）／SNS運用・マーケティング。（出典: shikaku-side.com, creators-academy.co.jp）
- **「非エンジニアの困りごとを1つ解決する」タイプの出品が売れやすい。** エンジニアがコード技術をそのまま売るより、業務課題（予約管理・請求書自動化等）に翻訳した方が刺さる。（出典: devsideup.com）
- **AI自動化系の実需要の実例**: Claude Code開発代行（30,000円〜）、AI記事自動生成ツール（15,000円）、RSS→SNS投稿文自動生成（22,000円）、複数サイト価格モニタリング（15,000円〜）、自動化相談（3,300円、漏斗の入口）、Excel月次レポート自動化（15,000円〜）。すべて実際にココナラで出品され成果物サンプルがGitHub公開されている。（出典: github.com/SHOW-17/ai-automation-samples）
- **AI活用で受注後の生産性を上げてサービスラインを増やす実例**: ブログ記事代行・SNS運用代行・データ分析レポートに加え、YouTubeシナリオ作成／Xツイート投稿代行（月額固定）／Instagramキャプション代行を追加し、月12万→20万円超に。ChatGPTのカスタムGPTで提案文自動生成（30分→5分に短縮）。（出典: note.com）
- **注意（一次情報の裏取りなし・体験談ベース）**: 「後発組は人気出品者の模倣では勝てない、レビュー数の先行者利益が強いサービス」という指摘あり。ニッチ特化（例:「宅建士・FP資格を活かした不動産・金融記事専門」）で差別化した方が勝ちやすい。（出典: ec.minikuru.co.jp, shikaku-side.com）

### F. 納品→検収→入金（★我々のwon=2/paid=0の詰まりポイント★）

7本中、検収プロセスそのものを深掘りした記事は薄い。得られた具体的示唆は以下のみ。

- **納品時は成果物だけでなく「使い方の簡単な説明」を添えると満足度が上がる。** その後に評価依頼メッセージを送るとレビュー獲得率が上がった。（出典: devsideup.com）
- **保守・サポート範囲を事前に決めておく。** 「納品後のちょっとした修正」が無限に続くケースがあるため、保守期間と回数をあらかじめ決めて明記する。要件確認を怠ると仕様変更の嵐に巻き込まれる。契約前に要件を文章化し、対応範囲外の作業は別料金と明記するのが鉄則。（出典: devsideup.com）
- **納期は絶対厳守。遅れそうな場合は事前連絡。** 同時受注は2〜3件までに抑える（本業との両立前提の助言だが、複数案件同時進行時の遅延防止という点で我々にも適用可）。（出典: devsideup.com, creators-academy.co.jp）
- **トラブル時はメッセージ内でやり取りを完結させておく。** ココナラ運営への相談窓口があり、取引メッセージ内で経緯が残っていれば運営が仲介しやすい。（出典: devsideup.com, creators-academy.co.jp）
- **手数料は販売価格の22%（税込）。** 例: 5,000円販売で手取り3,900円。価格設定時にこれを織り込む必要がある。（出典: shikaku-side.com, creators-academy.co.jp）
- ★**検収を通すコツそのもの（クライアントに「検収完了」ボタンを押させる具体的テクニック、催促文言、検収忘れ対策等）は、7本のどのソースにも書かれていなかった。** これはF項目で最も重要な欠落であり、我々の`won=2/paid=0`のボトルネックに直接効く情報がこの調査からは得られなかった。追加調査が必要（下記§4）。
