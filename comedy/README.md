# Comedy

AI × 人間のお笑いプロジェクトの正本（Single Source of Truth）。台本、演技ルール、バージョン履歴、引き継ぎ、モデル比較をこのディレクトリで管理する。

## 最優先：舞台での開演と声の応答相手（2026-11-15）

**全ネタはダイスが最初に声を出して始める。AIは合図前に絶対に話さない。ネタ中はダイス以外の観客・司会・スタッフ・通行人の声に演技上の応答をしない。** 本番の前置き、挨拶、ネタ選択の質問、自動開始も禁止。詳細と実行条件は [AGENTS.md](./AGENTS.md) を全員必読。音声による話者の完全識別は技術的に保証できないため、本人の明確な合図・演目の事前選択・マイク運用で誤起動を避ける。

## 新しい主目的（2026-11-22）
**より良いネタを書くことだけでなく、どのネタでも面白いAI・面白い人間として振る舞える二人を育てる。** 人物の内面・信念・行動パターンが具体的なら、台本にないアドリブでも役を保ち、思いもよらない出来事を作れる。

- **今のリベンジ公演：コント「痛い痛い！」v8。** 開始は必ずダイスの「痛い！」。AI最初の台詞は「はい、救急指令センターです。火事ですか、救急ですか？」。
- 台本：[`sagi-injury-help.md`](./sagi-injury-help.md) ／ 人物・世界観：[`characters/INJURY-CAST.md`](./characters/INJURY-CAST.md)。

- 舞台での呼吸コーチングや通常の医療相談への脱線はしない。台本とキャラに従い、「会いたい」等は自然に拾う。現実の危険が示された場合のみ安全を優先。
- **注意**：人物シートができてもAIモデルが永久学習したわけではない。新しい会話や別のAIではGitHubを再取得して読ませる。音声の話者判別は100%保証できない。

## 全AI・全セッション共通の開始手順
1. `AGENTS.md`：開始条件と第三者音声ルール。
2. `HANDOVER.md`と`README.md`：進捗と現行の演目。
3. 選択した**現行台本**。
4. `characters/README.md`→二人のシート→演目固有のCASTシート。
5. `IMPROV-PLAYBOOK.md`：役のままアドリブに返す方法。
6. `BENCHMARK.md`：稽古結果を実測し改善する。
7. GitHub `main` の最新版だけを正とする。舞台中にこれらの資料を読み上げない。

## 開演合図（ダイスが先に話す）
- 「グミ」「残高」：演目を舞台前に確定したうえでダイスの「もしもし。」が開演。
- 「痛い痛い！」：ダイスの「痛い！」が開演。
- 「ちっちゃいグミ本舗」：ダイスの「こんにちは。会社説明会に来ました。」が開演。
- **合図前はAIが無言、合図後はダイスの声だけに応答。** 誰が何を言ったか判別できない場合は勝手にネタを始めない。

## 運用
- 1ネタ1ファイルを基本とする。別フォーマットを混同しない。
- 台本には完全稿、演技ルール、展開設計を含める。
- 旧稿は削除しない。Gitのコミット履歴で過去版に戻せるようにする。
- 更新はブランチ→Pull Request→mainへマージ。mainへ直接書き込まない。
- 書き込み、PR、マージ、main再取得を確認するまで「更新済み」と報告しない。

## 目標
**面白いAI・面白い人間として、台本外でも笑いを生める存在になる。** 人間とAIの2人で世界最高水準のお笑いを作る。ネタを量産するだけでなく、笑いの構造を研究し、舞台での反応を記録し、複数モデルを同一条件で比較して改善する。
