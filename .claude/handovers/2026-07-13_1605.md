### B. ブラウザ基盤（`~/anicca/skills/browser/`）— 新規作成
Dais が挙げた4つの事故を全部塞ぎ、**実ブラウザで実証**した。

| 事故 | 真因（実測） | 処置 | 実証 |
|---|---|---|---|
| ディスク圧迫で Chromium が落ちる | profile 1個=1.0GB のうち **97% が捨ててよいキャッシュ**。それが5個 | 非稼働 profile のキャッシュ回収 + 起動時にキャッシュ上限（`--disk-cache-size=200MB`, `--disk-cache-dir=/tmp/cloak-cache`） | **13GB → 16GB free**。Cookies 全 profile 無傷 |
| タブが閉じられず溜まる | 応募のたびに新規タブ → 15個超 → メモリ枯渇（load 21超）→ Chromium 死 | `cdp_tab_gc.py`（毎パス + B2後）+ context release + 孤児 context GC | `reaped: ["clip"]` |
| 落ちるとログインが飛び、Dais が再ログイン | hard kill で cookie 消失 → 2FA → 人間が必要 | **セッション金庫** `session_vault.py`（cookie を30分毎に JSON 保存、復帰時に自動注入。launchd `ai.anicca.session-vault`） | **kill → 自己復帰 → Coconala ログイン維持** |
| ループ同士がタブを奪い合い壊し合う | 全員が同じタブを navigate | **`cdp_context_lease.py`** = ループごとに独立 BrowserContext（CDP 公式: "Similar to an incognito profile but you can have more than one"）。context は cookie を共有しないので金庫から seed | 2 context 同時取得 + **隔離 context で Coconala ログイン維持を実測** |

**棄却**: `--media-cache-size` / `--memory-pressure-off`（現行 Chromium に存在しないフラグ）、browserless(★13k) / steel-browser(★7k)（Docker でブラウザを量産する層で問題が違う）、`disk-cleaner が profile を消していた`説（実コードで sweep 対象外と確認）。
