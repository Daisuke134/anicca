## ハマりどころ

- **STARTUP の single-quoted 文字列内に literal single quote を注入して string を壊した**。`grep '"requestId": ...'` の単引用符がそのまま `STARTUP='...'` を閉じてしまい `File name too long` エラーで gig-cli.sh --restart が失敗。修正: `NEVER use grep substring search on the JSON` へ書き換え、literal quote 除去。教訓: **単引用符文字列内は quoted pattern を避ける、`grep -oE`/`grep -F` 等の言い換えで対応**。
- **os.utime(slot_dir, ...) は macOS で st_ctime を制御できない** ため test の age_days パラメータが効かず、dormant check が発火しなかった。→ `.slot_created` marker file (test でも prod でも同じ path で制御) に統一。
- **`rtk hook claude` の empty stdout を Claude Code 一部バージョンが Node.js CJS loader:1458 で reject**。絶対パス化だけでは insufficient。wrapper が「rtk が rewrite しなかった時は `{"hookSpecificOutput":{...,"permissionDecision":"allow"}}` を必ず emit」+ 末尾 newline で 8/500 → 0/500 に削減。残る 3/500 は複数行 Japanese command (`grep -c "編集する"`) 由来で Claude Code side の internal issue。
- **VCSDD orchestrator の state transition が厳格**: `1b → 2a` 不可、`1b → 1c → 2a` 必須。verdict.json も `reviewContext.mode`/`priorFindings`/`corroboratingEvidence` などのフィールドが AJV schema で拒否される → `jq 'del(...)'` で strip してから transition する。
- **legacy test の regression**: sprint-3 baseline (`test_dispatch_integration_roi.py` / `test_step3_recipe.py`) が sprint-4 (c)/(d) の変更を「invariant violation」として rejected。意図的な wire なので legacy test 側を updating (sprint-4 更新に整合)。VCSDD の "spec-fidelity vs legacy invariant" tension は本質、都度 rationalize して spec 側に record。

## 学び

- **VCSDD ≠ self-improving framework**。 VCSDD = correctness gate (inner)、outer = discovery engine が別途必要 (OIL draft を書いた理由)。誰もこの区別を明確にしていない SOTA 群の中で、我々は明示的に inner/outer 分離を宣言する立場が取れる。
- **spec REQ の "st_ctime" 等 platform-specific fs primitive** は spec の意図 (時間ベース age) を保ちつつ実装で置換して良い (marker file による semantics-preserving refactor)。この判断を Phase 2c refactor として commit + spec 更新でセルフ documenting すれば adversary もそのまま通る (実際通った、sprint-1 iter-1 impl adversary で "0 findings")。
- **hook error の root cause は 2 段階**: (1) PATH (headless tmux が rtk を resolve できない)、(2) empty stdout の JSON contract (一部 Claude Code versions が empty を loader:1458 で fail)。両方 fix しないと production headless session は寡黙に壊れる。system-wide hook は wrapper で defensive fallback を emit するのが安全。
- **anti-collision behavior が既に spec 済** (proactive-loop の a1 STARTUP)。restart 直後の pass が「他 agent と衝突リスク → skip」を選択するのは正しい設計。0 apply 報告を bug と誤診して重ねて restart するとむしろ有害。まず pane を観察してから判断する。
- **single-quoted bash strings に埋め込む可視 pattern は "quote 済み例示" ではなく "自然言語での禁止" で書く**。埋め込み quote の防御コスト >> 表現力。教訓: STARTUP prompt を編集する時は「literal quote は禁忌」を先頭に置く。
