## 決定事項
- **設計 v2**: MCP 層は自前 settle しない。X-PAYMENT を serve-v2 に forward（薄い protocol 変換層）。
- executor: Sol/Luna は **codex provider の token 切れ（429 cooling down）**。Dais 裁定「no sol, no luna, you yourself」
  → **Fable 本体が直接実装**（このセッションで実行済み）。復活するまで subagent 実装は使わない。
- funnel 増設ではなく path 分岐（`--set-path=/mcp`）で /mcp を公開（funnel は 443/8443/10000/10001 の4個が上限）。

## 捨てた選択肢と理由
- serve-v2 への internal-bypass middleware 追加 → 不要になった（forward 設計で serve-v2 無変更を達成。触らない方が安全）。
- MCP 層での verifyAndSettlePayment 自前実行 → 二重払いリスク + 決済ロジック分散。forward 一択。
- funnel 用の新ポート → 存在しない（Tailscale の仕様で4ポート固定）。path 分岐が正解。
