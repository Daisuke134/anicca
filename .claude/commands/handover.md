# セッション引き継ぎノート生成

セッション終了時や作業の区切りで、引き継ぎノートを生成する。

## 手順

1. 今回のセッションで行ったことを振り返る
2. プロジェクトルートの `.claude/handovers/` ディレクトリが存在しない場合は作成する
3. `YYYY-MM-DD_HHmm.md` のファイル名で引き継ぎノートを生成する（例: `2026-02-17_1430.md`）。時刻は `date +%Y-%m-%d_%H%M` で取得する
4. 既存のファイルと同名になる場合は末尾に `_2` などの連番を付与する

## 引き継ぎノートの構成

必ず以下のセクションを含める。該当なしのセクションは「なし」と記載する。

### 今回やったこと
- 作業内容と進捗を箇条書きで

### 決定事項
- 確定した設計判断、方針、ルールなど

### 捨てた選択肢と理由
- 検討したが採用しなかったアプローチとその理由

### ハマりどころ
- 詰まったポイント、エラー、想定外の挙動など

### 学び
- 今回得られた知見、気づき

### 次にやること
- 未完了のタスク、次のセッションで着手すべきこと（優先度がわかるように）

### 関連ファイル
- 今回触った主要ファイルのパス一覧

### 新セッション開始プロンプト
- 次の agent がそのまま貼って開始できる「正確なプロンプト」を1つ用意する

## ルール
- 簡潔に。箇条書き中心。推測や曖昧表現を避け事実ベースで。
- 「捨てた選択肢と理由」は特に重要（次セッションで同じ議論を繰り返さない為）。
- 末尾で「新セッション開始プロンプト」を Dais のメール(keiodaisuke@gmail.com)へ送る（gog gmail / Resend）。
