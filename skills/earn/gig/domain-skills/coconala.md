# domain-skill: coconala

サイト固有の操作事実。**推論では出ない。実物を開いて初めて分かったものだけを書く。**
新しく詰まった所を解いたら、その場でここに1行足す（案件が終わってからでは忘れる）。

各項目の形式: `事実` → `知らないと起きること`（実際に起きた事故は日付を残す）

---

## 会話を読む

- **`過去のメッセージを読み込む` / `過去のメッセージを見る` を、消えるまで押す。**
  既定では直近数件しか描画されない（買い手C 49件・jobeai 22件が隠れていた）。
  → 押さないと上端の「ご購入ありがとうございます」だけを見て「対応不要」と判定する。
    2026-08-04、これで24 pass 空回りし、買い手がキャンセルを申し出た。

- **買い手の添付は DM 側に来る。** トークルームの `buyer_attachments` は空のことがある。
  指示書・認証情報・素材は `coconala.com/mypage/direct_message/<thread_id>` にある。
  → 「素材が無いので着手できません」と誤診する。2026-08-04 の永久 blocked の真因。

- 情報源は最低4つ。**全部開くまで「context が無い」と言ってはならない。**
  1. トークルーム本文
  2. **DM スレッド**（`/mypage/direct_message/<id>`）
  3. トークルームの **ファイルタブ**
  4. 直接依頼ページ（`/direct_offers/edit/<offer_id>`）

- トークルーム右パネルに **クローズ日 / 定期購入の回数 / 取引開始日**が出る。
  定期購入は毎月クローズし、**クローズごとに評価が発生する**。

## 取引と提案

- **見積り提案の購入期限は送信から1週間。** 提案を編集すると期限がリセットされる。
  → 気づかず失効する（jobeai の月40,000円提案は 8/1 送信 → 8/8 失効）。
- 提案編集画面 `/mypage/direct_offers/<offer_id>` のカテゴリは**変更できない**（表示のみ）。
- 定期購入の提案は「提案額(月額) / 2ヶ月目以降の割引率 / 最低継続期間」を持つ。
- トークルームがクローズ済みの相手には**メッセージ機能**で連絡する。
- DM の添付は `input[type=file][name="data[DirectMessage][attachments][]"]` に
  `DOM.setFileInputFiles` で載る。**UI にファイル名チップが出なくても送信には乗る**（2026-08-05 実測）。

## 応募

- 応募一覧: `/mypage/job_matching/applied/offers`
- 取り下げ: `/mypage/offers/<offer_id>` → 「応募を削除する」→ モーダルの「削除する」
- ★実写動画の編集は請けない★（過去に★1評価。判断根拠は `application_planner.py` の prompt が正本）

## 出品

- **実写素材の編集を募集する出品を公開しない。** 過去★1は応募だけでなく出品（サービス94000007
  「SNS縦型ショート動画を1本編集します」）でも起きた — 出品しておくと買い手がそれを見て発注し、
  同じ失敗が応募を経由せず直接発生する。判断根拠は `application_planner.py` の prompt が正本、
  同じ no-go を `listing_inventory.py` の `KNOWN_NO_GO` にも複製済み。
- 取り下げ（archive）: `/mypage/services_lists` の各出品カード「公開設定」ポップオーバー →
  「アーカイブする」→ 確認モーダルの「OK」（`<a href="/services/archive/<id>">`、plain link、
  onclick/data-methodなし）。実行は `python3 skills/earn/gig/scripts/listing_archive.py archive
  <id> --reason <reason>`。効果はCoconala自身の確認モーダル文言の通り: 検索・カテゴリ・
  プロフィール一覧から消えるが、**既存のトークルーム・評価・直リンクはそのまま残る**（進行中の
  取引には影響しない）。

## 数字の読み違い

- **ビューアが番号体系を2つ持つことがある。**
  `southern-dsc.co.jp` のカタログ（sdsCat）は 目次 = 生 index、ページ入力欄 = index+1。
  → 買い手の「73ページ」と指示書の「74ページ目」が矛盾に見えるが**同一ページ**。
    番号の生成コードを読むまで、どちらが正しいか決めてはいけない。

## 評価

- 高評価の依頼・見返りの提示は**禁止行為**。評価に言及しない。
- 出品者が48時間無応答 → 自動キャンセル + **自動★1**。
- 出品者が4日無応答かつ買い手が最終発言者 → 買い手のキャンセル申請 → 24時間で成立 →
  **自動★1 + 全出品が受付休止**。
- ★1が1回入るとプラチナ維持（直近3ヶ月平均4.8）に**★5が約20件必要**。

## 納品の制約

- ★外部ツールでの納品は禁止★（Google Drive / GitHub / note / Dropbox 等を名指しで禁止）。
  例外は①ギガファイル便（サイズ超過時のみ）②買い手がトークルーム／DMで明示的に
  「グーグルドキュメントで」等 Google ドキュメント形式を指定した場合のみ。
  ②は成果物ファイルの添付は今まで通り行った上で追加で、
  `python3 skills/earn/gig/scripts/google_docs_publisher.py --input <成果物パス> --title "<件名>"`
  を実行する（gog CLI、account は `$GIG_GOG_ACCOUNT`（未設定時 `operator@example.com`）、role=commenter で自動共有）。
  標準出力 `{"ok":true,"file_id":...,"link":...}` の `link` を
  `delivery/paid-work-result.json` に `google_doc_link` として追加すると、
  納品メッセージにそのリンクが載る。`ok:false` は失敗なので通常のファイル添付のみで納品する。
  買い手の指定が無い限りこの手順は使わない。
  → 91000001（2026-08-07）「納品はGoogleドキュメントでお願いします」。
- 添付上限: トークルーム 200MB / メッセージ 100MB / 1メッセージ最大5ファイル。
