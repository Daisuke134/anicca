## Delivery and inquiry cadence (deterministic policy)

Paid or buyer-feedback work is never blocked from buyer-visible progress. Reopen
the live talkroom first, then send the current version (only if a real artifact
exists) together with the acceptance delta and every observed blocker. Keep the
formal-delivery checkbox off until the versioned artifact, acceptance evidence,
package hash, and buyer agreement are all independently observed. After any
formal submit, the next collector pass must observe the transaction step
`納品確認待ち`; a local checkbox flag is not evidence.

The collector also builds an inquiry queue from open talkrooms. For each row
whose live DOM shows a buyer waiting, reopen that room, read the current request,
send one concrete reply with the next input and earliest feasible date, and save
post-send URL/screenshot evidence. The queue contains only request-scoped room
ids/URLs and bounded titles; customer names and raw message bodies are not
persisted.
