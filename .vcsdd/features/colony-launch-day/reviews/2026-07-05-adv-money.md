### FINDING 1 (CRITICAL, confirmed LIVE) — surplus gate is a yes/no switch, not an amount cap; the daemon that uses it is actually running in production

`skills/ubi/ubi-payout-watcher.mjs:140-195`. The "#5b realized-surplus gate" computes
`gate = contribute(realized, bal/1e6, {...})` and only ever checks `gate.amount_usd <= 0` (line 142) to
decide whether to DEFER the whole pass. After that check, `gate.amount_usd` is **never read again**. The
actual amount paid out is `payAmountBase = Math.min(STIPEND_BASE, PERTX_CAP_BASE)` (default $0.25,
line 158), paid to **every** queued recipient in a loop that only stops when
`bal - payAmountBase < RESERVE_BASE` (default $1, line 177-180).

Consequence: as little as $1.0000001 of realized profit (the default `REALIZED_THRESHOLD_USD`) is enough
to flip the gate open — the 10%-of-profit figure the gate computed (in this example $0.10) has zero
bearing on the following payout loop, which will then drain the wallet from whatever its balance is down
to the $1 reserve floor, one $0.25 stipend at a time, across as many queued recipients as exist. The
"link distribution size to real earnings" fix (Task #5b's stated purpose, per the file's own header
comment) only links the *trigger*, not the *magnitude*.

This is not a hypothetical/dead code path: `com.anicca.ubi-watcher` is a loaded launchd job
(`launchctl list | grep ubi` → job present) whose `ProgramArguments` run
`skills/ubi/ubi-watcher-daemon.sh`, which `exec`s `node .../ubi-payout-watcher.mjs --loop` — i.e. this
exact function is the live, always-on money-moving loop, not a demo script.

Repro: read `pass()` at `skills/ubi/ubi-payout-watcher.mjs:134-196` — `gate.amount_usd` is bound at line
141 and read only at line 142; no later line references it.

### FINDING 2 (HIGH, confirmed) — gojo's ≤1-gift/24h rate limit is never actually enforced by its only caller

`skills/economy/ubi/ubi.js:82` correctly implements the 24h rate-limit as pure logic
(`(recentGifts || []).some(g => ... now - g.ts < windowMs)`), and `skills/economy/ubi/state/gojo-log.jsonl`
durably records every decision (confirmed non-empty, contains a real prior gojo decision). But the ONLY
caller, `skills/economy/ubi/run.sh:128`, invokes it as:

```js
const r = distributeAI('$RECIPIENT_WALLET', $SURPLUS, registry, []);
```

`recentGifts` is a **literal, hardcoded empty array on every single run** — the gate never reads back
`gojo-log.jsonl` to reconstruct history. Grepped the whole repo for any reader of `gojo-log` or any other
producer of `recentGifts`: none exists. Today this is a "PLAN ONLY, NOT EXECUTED" pipe (confirmed: line
135's own comment, and no wiring to `execute-ubi.py` from this script), so no money is actually lost yet —
but the safety property the code comments claim ("REQ-DRAIN: <=1 gift/24h per recipient") is false the
moment this plan gets wired to real execution, because the rate-limit input is structurally incapable of
ever being non-empty.

### FINDING 3 (HIGH, confirmed) — untrusted network/file data is spliced into `node -e` source text, not passed as data

`skills/economy/ubi/run.sh:43-47` and `:125-130` build the gate call by directly interpolating bash
variables (`$REALIZED`, `$LIQUID`, `$SURPLUS`) — themselves derived from a live HTTPS fetch of
`aniccaai.com/.netlify/functions/dashboard-sync` and from local `telemetry.json` files — straight into a
`node --input-type=module -e "..."` script body:

```bash
CONTRIB_RESULT=$(PYTHONWARNINGS=ignore node --input-type=module -e "
import { contribute } from '$HERE/ubi.js';
const r = contribute($REALIZED, $LIQUID);
...
```

This is source-code templating, not numeric substitution. Any run in which `monthly_revenue_usd` (or a
telemetry balance) is not literally a bare JS numeric token turns into either a JS syntax error (falls
back to the `CONTRIB_RESULT` empty-string fail-closed default — the common, safe outcome) or, if an
attacker can ever get a crafted string value into that leaderboard row, arbitrary JS execution in the
node process reading `ubi.js`. Compare with the SAFE pattern already used one file over, in
`ubi-payout-watcher.mjs:45-55`'s `realizedProfitUsd()`, which does `Number(row.monthly_revenue_usd)` +
`Number.isFinite()` inside real JS (`fetch()` + `.json()`), never as bash-interpolated source text. `run.sh`
should use the same pattern instead of `node -e` string-building.

### FINDING 4 (MEDIUM, confirmed, currently latent) — `contribute()`'s own header claims a fail-closed guarantee the code does not enforce for `config`

Header (ubi.js:9): *"Fail-closed everywhere: any missing/invalid/non-positive input means NO
distribution — never guess."* Verified live that this holds for the two positional numeric arguments, but
NOT for the `config` object:

```
contribute(10, 100, { contributePct: -0.5 })  ->  { amount_usd: -5,  reason: "-50% of $10 realized profit" }
contribute(10, 100, { contributePct: 5 })     ->  { amount_usd: 50,  reason: "500% of $10 realized profit" }
contribute(10, 100, { reserveUsd: NaN })      ->  { amount_usd: 1,   reason: "10% of $10 realized profit" }  (reserve check silently skipped)
contribute(10, 100, { reserveUsd: -1000 })    ->  { amount_usd: 1,   reason: "10% of $10 realized profit" }
```

No range/finiteness check exists on `contributePct`, `reserveUsd`, or `contributeThresholdUsd`. Neither
of the two current callers passes an attacker-influenced config today (`ubi-payout-watcher.mjs` only
overrides `contributeThresholdUsd` from an operator env var; `run.sh` passes no config override at all),
so this is not exploitable through the currently-wired paths — but the code does not actually back the
invariant its own comment asserts, and a future caller (or a misconfigured env var flowing into a wider
config object) would silently break it.

### FINDING 5 (LOW, confirmed) — `distributeAI()` crashes instead of failing closed on a wrong-typed `recentGifts`

```
distributeAI(REGISTRY[0], 100, REGISTRY, {to: REGISTRY[0], ts: Date.now()})
  -> TypeError: (recentGifts || []).some is not a function
```

`(recentGifts || [])` only guards falsy values (`null`/`undefined`), not truthy-but-wrong-typed ones (an
object instead of an array). Behaviorally this still prevents a wrongful payout (the exception aborts
before an amount is returned), so it is not a fund-safety hole today, but it violates the module's
"never guess, no-op" philosophy — a crash, not a graceful `{amount_usd:0}` — and is uncovered by
`ubi.test.mjs`.

### FINDING 6 (CRITICAL, confirmed, reproducible) — `earnings_delta_usd = NaN` bypasses the "positive number" gate and would trigger a real merge

`skills/_shared/lib/bot2bot.py:184-186`:

```python
earnings_delta = verdict.get("earnings_delta_usd")
if not isinstance(earnings_delta, (int, float)) or isinstance(earnings_delta, bool) or earnings_delta <= 0:
    return False, f"earnings_delta_usd is not a positive number (got {earnings_delta!r})"
return True, "tests_pass=True, adversary_verdict=PASS, earnings_delta_usd>0"
```

`float('nan')` IS an instance of `float`, is NOT a `bool`, and `nan <= 0` evaluates to `False` under
IEEE-754 (NaN compares False against everything, including `<=`). So none of the three OR-conditions
trip, and the function falls through to `return True, ...`.

Reproduced live:
```
_merge_gate({"tests_pass": True, "adversary_verdict": "PASS", "earnings_delta_usd": float("nan")})
  -> (True, "tests_pass=True, adversary_verdict=PASS, earnings_delta_usd>0")
```

Since `auto_merge()` (line 198) does `ok, reason = _merge_gate(verdict)` and merges iff `ok`, this verdict
would make `auto_merge()` actually call `_gh_call("pr", "merge", str(pr_number), "--squash",
"--delete-branch")` — a real merge — for a PR whose claimed "earnings delta" is not a real number at all.
This directly contradicts the function's own docstring: *"Fail-closed: any missing/malformed verdict
field means 'do not merge' (never guess a PASS)."* NaN is exactly the malformed-field case that slips
through, and it is not covered by the existing 6 auto_merge tests in `test_bot2bot.py` (which test
missing keys, `False`, `"FAIL"`, and `0`, but never `NaN`).

Mitigating context (does not change the FAIL verdict, only its blast radius today): grepped the entire
repo for `auto_merge(` and `earnings_delta_usd` — the only occurrences outside `bot2bot.py` itself are in
its own test file. **No live caller wires a real "earnings_delta_usd" computation to this function yet**
(no cron, no `self/*` skill), so no PR has been auto-merged via this NaN path today. But `NaN` is a
realistic value the moment a delta computation like `(after - before) / before` is wired up with
`before == 0`, or a failed/uninitialized computation defaults to `nan` — this is precisely the kind of
"型混同" adversarial input the review was scoped to test, and it is confirmed to defeat the gate as
written.

### Type-confusion checks — all PASS (no finding)

Verified `_merge_gate` correctly rejects, via direct calls:
- `tests_pass` as the string `"true"` or the int `1` (only the literal `True` singleton passes, because
  the check uses `is not True`, not `!= True`/truthiness).
- `adversary_verdict` as `"pass"` (lowercase) or `"PASS "` (trailing space) — exact string match required.
- `earnings_delta_usd` as `0`, `-5`, the string `"10"`, `None`, missing entirely, or the bool `True`
  (explicitly excluded via `isinstance(x, bool)` guard, since `bool` is a subclass of `int` in Python).

### FINDING 7 (LOW, confirmed) — non-dict `verdict` crashes rather than gracefully failing closed

`_merge_gate(None)`, `_merge_gate([1,2,3])`, `_merge_gate("not a dict")` all raise `AttributeError:
'...' object has no attribute 'get'`. Since this happens on the first line of `_merge_gate`, called
before any `gh pr merge`, the crash does propagate up through `auto_merge()` and prevents a merge — so
this does NOT cause a wrongful merge — but it also means the decision is never appended to
`auto-merge-log.jsonl` (the crash happens before that `append_jsonl` call), leaving no audit trail for a
malformed-shape verdict. Low severity: an observability gap, not a fund-safety gap.

## Overall CONFIRMED findings, by severity

1. **CRITICAL** — `_merge_gate()` approves a merge when `earnings_delta_usd` is `NaN` (bot2bot.py:184-186). Not yet wired to a live caller, but defeats the stated fail-closed invariant outright.
2. **CRITICAL** — `ubi-payout-watcher.mjs`'s live, running `--loop` daemon uses the realized-surplus gate only as an on/off switch; the actual per-pass payout total is unbounded by the gate's own computed amount and can drain the wallet to the $1 reserve floor regardless of how small the "sanctioned" contribution was (ubi-payout-watcher.mjs:140-195).
3. **HIGH** — gojo's 24h rate-limit can never actually trigger because `run.sh` always passes `recentGifts=[]` (economy/ubi/run.sh:128); currently harmless only because this pipe doesn't execute transfers yet.
4. **HIGH** — `economy/ubi/run.sh` splices untrusted network/file-derived strings directly into `node -e` source text rather than passing them as data (run.sh:43-47, 125-130) — a code-injection-shaped defect regardless of current exploitability.
5. **MEDIUM** — `contribute()`/`distributeAI()` do not validate `config` override shape/range, contradicting the module's own "fail-closed everywhere" claim (ubi.js, config path only — not the two positional numeric args, which are solid).
6. **LOW** — `distributeAI()` throws instead of failing closed on a wrong-typed `recentGifts` (ubi.js:82).
7. **LOW** — `_merge_gate()`/`computeSpawnGate()` throw on `None`/non-object input instead of returning a graceful reject; no fund-safety impact since the crash itself blocks any subsequent tx/merge call, but no audit-log entry results.

**Dimension 2 (SPAWN-READ-ONLY) is genuinely clean — PASS, no findings block it.**
**Dimensions 1 and 3 are FAIL** — the money-moving gates read correctly on the happy path and reject most textbook malformed inputs, but each has at least one confirmed, reproducible hole (unbounded live payout size in dimension 1; NaN bypass in dimension 3) that a careful adversarial pass surfaces and the existing test suites do not cover.
