## GREEN behavior

1. The three scoped settings render native labeled `<select>` controls with the exact command allowlist values. The browser test uses desktop and 375px mobile viewports, performs `selectOption`, observes the real shared `/api/panel/commands` response, records the exact typed commands, reloads, and reads back the scoped values.
2. The SQL RPC locks the presented row, atomically commits the first candidate child hash plus a non-bearer seed digest, and returns that committed seed to every request in the grace window. Each server derives the same raw child and verifies its hash before setting a cookie. No later request deletes or replaces a response child. Logout/rebind/tenant revoke clear the whole applicable family; raw bearers remain hash-only at rest.
3. Verified activity extends `idle_expires_at` by 30 days and returns `cookie_max_age`; page/API/OAuth responses use that exact result. There is no enforced absolute day-180 boundary. Rotation creates another member of the same family; normal activity can continue until logout, rebind/security revoke, browser storage removal followed by idle expiry, or a genuine idle expiry. Idle expiry revokes the family.
4. Production batch preferences accept defaults only after a successful array parse. JSON parse failure or any non-array body returns every affected user with calls, notifications, and DAILY automation false; a valid empty array retains documented defaults.
