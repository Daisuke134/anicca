## Bug found + fixed live during this E2E (real regression, not simulated)

**First run** failed `gig_verify_and_pay` with `insufficient_funds` immediately after a real,
successful `gig_post` escrow-funding settle. Root cause: the facilitator's `/settle` response confirms
the tx was *broadcast*, not mined; the immediately-following release settle's own on-chain balance
preflight raced ahead of confirmation (both operations ran within the same Node.js event loop tick).
Confirmed by checking the post tx's receipt (`status:"0x1"`, success) and the escrow's USDC balance
moments later (`0.001 USDC` — the funding HAD landed, just not yet when the release settle's preflight
ran).

**Fix**: `lib/escrow.mjs`'s `settleBody()` now calls `publicClient.waitForTransactionReceipt({hash})`
after `/settle` returns and only reports `ok:true` once the tx is actually mined on-chain. Re-ran the
full loop clean afterward (table above) — no race, real payout tx.
